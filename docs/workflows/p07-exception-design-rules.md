# P07 全病理异常场景设计规则

文档状态：已完成
文档版本：0.1
创建日期：2026-08-06
适用范围：P06-ALL-MODALITY-FINAL 之后的异常识别、影响判断、阻断、处置、补偿、恢复和追溯。

## 1. 阶段边界

P07承接P06的异常入口，定义异常的业务含义、影响范围、患者安全等级、阻断和恢复方向。P07不展开P08对象状态设计、P09需求基线、P10架构和技术事务、P11数据承载、P12字段契约、P14详细权限点、P24页面、P25测试实现、代码、部署或运维实现。

## 2. 正式规则

### P07-RULE-001：异常必须来源明确

每个正式异常至少追溯到一项P06异常入口、正式场景、已确认决策、领域对象、聚合、正式不变量、真实Q编号或P06遗留风险。通用经验只能标记为“待后续需求确认”，不得伪装为已确认结论。

### P07-RULE-002：正常分支与异常分离

正常病理类型分流、扫描可选、独立/附属分子模式、直接涂片/液基制片、正常报告补充、授权代理和符合规则的复测不自动形成异常。只有偏离预期、产生风险、需要裁决、补偿、阻断或保留异常证据时才形成正式异常。

### P07-RULE-003：局部影响原则

异常默认只影响相关申请、病例、标本、蜡块、玻片、数字切片、细胞学制备物、检测材料、提取物、检测任务、检测结果或报告版本。必须有明确影响依据才能扩大到病例、批次或外部回传范围。

### P07-RULE-004：高风险身份冲突阻断

患者、就诊、病例、标本、蜡块、玻片、分子材料、报告患者归属或外部结果归属无法确认时，至少阻断相关对象，不得继续形成新的诊断或正式报告事实，直至完成授权核对。

### P07-RULE-005：历史事实不可删除

异常处置不得删除、覆盖或伪造原身份、原编号、原来源、原执行、原检测结果、原诊断依据、原报告版本、原接口事件、原责任记录或原审计证据。纠正、撤回、作废和销毁均形成新事实。

### P07-RULE-006：业务异常与技术故障分离

必须分别表达业务规则异常、患者安全异常、材料/来源异常、质量异常、技术故障、设备故障、接口投递失败、外部业务冲突、权限/责任异常以及灾备/恢复异常。技术故障可以触发质量评估，但不自动等同质量事件。

### P07-RULE-007：异常与质量事件分离

不是每个异常都自动建立质量事件。出现患者安全影响、错患者/错病例/错材料、错误报告已签发或发送、材料不可逆损失、错误结果被使用、重复性缺陷、制度要求或无法恢复来源责任链时，必须评估升级质量事件。

### P07-RULE-008：异常与审计分离

异常记录表达业务偏差和处置；审计事件表达谁在何时对什么对象执行了什么操作及结果。异常、质量事件和审计证据不得合并为万能日志。

### P07-RULE-009：未受影响对象允许继续

矩阵必须明确被阻断、被隔离、允许继续的对象，是否允许部分报告、其他检测任务或同批其他样本继续。无依据不得全局停用。

### P07-RULE-010：报告影响独立评估

异常必须分别判断未形成报告、草稿、已审核未签发、已签发未回传、已签发并回传、已被临床使用以及存在后续综合报告等阶段，不得以一个“报告异常”代替分阶段处置。

### P07-RULE-011：外部事实分层

本地事实、出站事件、投递、外部接收、外部生效和对账必须分别判断。外部业务状态不得覆盖本地申请、病例、结果或报告事实。

### P07-RULE-012：自动恢复边界

只有明确的技术性、可恢复、幂等、不会产生新业务事实、不覆盖更新版本、不涉及身份判断且次数和范围受控的错误，才允许自动重试或自动恢复。失败历史必须完整保留。

### P07-RULE-013：人工裁决责任

医学判断、身份判断、材料使用决定、报告影响判断和高风险纠错必须由授权业务人员裁决。系统管理员和服务身份不得替代业务负责人作出医学或业务结论。

### P07-RULE-014：异常编号唯一稳定

正式异常编号为 `P07-EXC-001` 起的连续编号。编号稳定、唯一，不按严重程度、病理类型或医院配置重新编号；合并、拆分和覆盖均保留原P06入口。

### P07-RULE-015：不预设异常总数

异常总数由108个P06异常入口、跨流程异常、患者安全关键异常以及实际去重和拆分结果共同决定。不得为达到数量重复拆分，也不得合并不同责任、阻断或恢复规则的异常。

### P07-RULE-016：严重程度与业务影响分离

每个异常同时记录患者安全等级、业务影响、阻断范围、处理时限、人工裁决要求和质量事件评估要求。严重程度不是单纯的技术优先级。

### P07-RULE-017：补偿必须关联原事实

返工、重制、复测、补测、外送、重投、撤回、更正、重新签发和恢复均必须关联原异常、原对象、原责任和原版本，不得以新结果抹除失败链。

### P07-RULE-018：恢复必须有开放条件

恢复方向必须说明修复事实、身份核对、来源核对、版本核对、文件核对、外部状态核对、授权复核和局部开放条件；未完成核对时保持隔离。

### P07-RULE-019：跨流程异常必须保留入口集合

一个P07异常可以覆盖多个P06入口，但必须保留全部入口编号、原流程和原追溯；如责任、严重度、阻断、报告处置或恢复方式不同，必须拆分。

### P07-RULE-020：P07后续输入分层

异常矩阵向P08输出对象和状态影响方向，向P09输出需求候选，向P10输出事务/幂等/隔离/补偿问题，向P14输出授权审批要求，向P25输出可验证的异常条件。P07不替代这些阶段的正式设计。

## 3. 严重程度

| 编号 | 含义 | 默认要求 |
|---|---|---|
| `P07-SEV-1` | 患者安全关键 | 相关对象阻断、立即隔离、授权裁决、报告/回传影响评估、质量事件评估、完整通知和证据保留 |
| `P07-SEV-2` | 高风险业务异常 | 相关对象隔离或阻断、业务责任人裁决、补偿/恢复方向和质量升级评估 |
| `P07-SEV-3` | 受控业务异常 | 局部待处理、退回、返工或受控关闭，保留事实并明确责任 |
| `P07-SEV-4` | 低风险或技术性异常 | 允许受控自动重试或局部补偿，不产生新业务事实，保留失败历史 |

严重程度可以由实际影响升级，但不得降低已确认的患者安全关键等级。具体阈值或时限由医院配置决定；核心阻断、来源核对、责任和历史保护规则不变。

## 4. 记录字段最低要求

`P07-EXC-*`正式异常至少具备：异常名称、分类、适用病理类型、来源、触发条件、检测环节、流程/步骤、影响对象、聚合、严重程度、患者安全影响、影响范围、阻断范围、未受影响对象继续规则、自动重试资格、即时处置、业务裁决角色、核对依据、补偿/恢复方向、历史保护、报告影响、外部系统影响、通知、审计、质量升级、关闭条件、P08/P09/P10/P14/P25输入和场景/决策/不变量/Q追溯。
