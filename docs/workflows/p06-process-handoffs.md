# P06 全病理业务流程衔接与业务流图

状态：P06已设计
本文件定义流程之间传递的业务对象、条件、责任和失败影响。图中只使用业务概念，不把具体系统实现当作流程节点。

## 1. 衔接登记规则

每条衔接必须同时记录：上游流程、下游流程、传递对象、传递条件、责任交出方、责任接收方、是否签收、失败影响范围、异常入口和关联不变量。传递对象是已形成的业务事实或事实引用，不是一个可被下游任意改写的共享状态。

## 2. 全病理业务分流总览

```mermaid
flowchart LR
    A[申请或外部材料] --> B[病例与病理类型识别]
    B --> C{业务类型}
    C -->|组织| D[组织取材与制片]
    C -->|术中冰冻| E[冰冻轮次与反馈]
    C -->|妇科/非妇科/穿刺细胞| F[细胞学制备与诊断]
    C -->|分子| G[分子材料与检测]
    C -->|外送| H[外部机构交接与结果核验]
    D --> I[诊断与报告]
    E --> I
    F --> I
    G --> I
    H --> I
    I --> J{是否需要多模态综合}
    J -->|是| K[综合诊断与综合报告]
    J -->|否| L[组成报告或结果]
    K --> M[回传、对账与档案]
    L --> M
```

## 7. 外送检测衔接

```mermaid
flowchart LR
    A[本地检测任务] --> B[材料核对]
    B --> C[外部机构与交接]
    C --> D[出站业务事件]
    D --> E[外部签收状态]
    E --> F[外部执行状态]
    F --> G[外部结果或报告]
    G --> H[来源与材料核验]
    H --> I{是否可用于本地判读}
    I -->|是| J[有效结果或外部依据]
    I -->|否| K[隔离并对账]
```

外送流程的失败影响通常限于当前材料、当前检测任务、出站事件或结果关联；不得因外部迟延自动撤销已形成的本地申请、病例或材料事实。

## 13. 交接的统一完成条件

只有在传递对象、来源版本、责任交出方、责任接收方、签收状态和失败影响范围均已形成时，衔接才可标记完成。下游失败只改变下游处理方向，不删除或回滚上游已经形成的申请、病例、材料、运行、结果或报告事实。
