## 1. P11逻辑敏感等级

| 等级 | 含义 | 典型数据 | 读取/导出/审计边界 |
|---|---|---|---|
| D1 | 患者直接身份和就诊上下文 | 外部患者号、就诊号、患者就诊快照 | 最小必要读取；导出脱敏；访问和纠错审计 |
| D2 | 敏感医学和诊断信息 | 标本来源、诊断正文、报告、分子结果、外部报告 | 医学责任和授权读取；导出审批；全链路审计 |
| D3 | 内部业务、责任和治理信息 | 操作者、授权、异常、质量、纠错、对账 | 角色受控；高风险操作强认证；审计追加 |
| D4 | 一般配置和技术元数据 | 代码集、系统目标、逻辑能力、非敏感技术引用 | 配置责任模块维护；变更留痕；导出限制按配置 |

该分类只用于P11数据设计，不替代P14正式权限矩阵、医院制度或法规判定。

## 3. 安全设计边界

- 数据库管理员权限不等于业务修改授权；P11只记录授权引用和治理证据，完整权限矩阵留给P14。
- 患者、诊断、分子结果和原始外部消息不得进入普通应用日志；日志只能使用内部引用、摘要和关联标识。
- 高风险纠错、报告撤回、销毁、恢复开放和材料不足裁决必须记录实际个人身份、授权范围、强认证引用和第二人复核要求。
- 文件存储引用本身属于敏感元数据；不得把存储凭证、服务器地址或未脱敏外部内容写入业务备注。
- 备份和恢复必须遵循冻结、归档、销毁、版本和审计关系；恢复校验未通过时保持隔离。

## 4. 归档、冻结、销毁和恢复

P11不把所有表统一设置软删除。归档和销毁按业务事实类别处理：

1. 临床事实先进入冻结或受控关闭，再评估保留依据；冻结期间禁止普通纠错和销毁。
2. 报告版本、诊断版本、原始检测结果、质控、审计、责任交接、原始消息和投递尝试只追加，销毁记录不能删除其历史证明。
3. 文件元数据、文件完整性和实际存储删除分别记录；文件丢失不删除报告、结果或诊断事实。
4. 恢复任务先隔离，再校验对象身份、版本、业务关系、文件完整性和审计连续性，最后由授权流程决定业务重新开放。
5. 已销毁对象不得因技术恢复重新成为有效业务对象；恢复只能形成恢复校验和差异事实。

## 5. 分区、容量和保留参数

审计事件、状态转换历史、入站原文、发件箱、收件箱、投递尝试、设备原始结果、文件元数据、异常质量历史、业务大表和数字材料元数据均保留分区能力，但当前不硬编码分区键、周期或物理分区方案。P09-PARAM-014、P09-PARAM-017和P09-PARAM-018仍未确认；其影响只登记为后续平台和容量输入。
