# P08 全病理对象状态机设计规则

文档状态：P08 已设计
阶段：P08-ALL-MODALITY-FINAL
基线：63 个对象、18 个聚合、70 条不变量、73 个场景、36 个流程、216 个步骤、108 个决策、108 个异常入口、26 个 SEV-1、1,220 个 Q

## 1. 规则

1. **P08-RULE-001**：状态机只描述有稳定身份、责任边界和可核验业务事实的对象或独立任务；流程步骤不是对象状态。
2. **P08-RULE-002**：对象、聚合、业务流程和异常记录分开建模；一个病例不得成为所有下游对象的万能状态容器。
3. **P08-RULE-003**：每个状态必须有对象、业务含义、进入事实、离开事件、责任角色和可验证出口。
4. **P08-RULE-004**：每次状态转换必须由已形成业务事件触发，并保留触发人、服务或设备、时间、来源和依据。
5. **P08-RULE-005**：状态转换必须声明前置条件、业务守卫、责任角色、形成事实、失败影响、重试方向、审计要求和 P07 异常编号。
6. **P08-RULE-006**：对象状态不替代对象身份、来源、标签、材料、结果、责任、报告版本或投递事实。
7. **P08-RULE-007**：原始消息、设备原始结果、质控结果、外部结果、责任记录、交接记录和审计事件作为不可变事实保存，不因下游状态改变而改写。
8. **P08-RULE-008**：报告、诊断、患者与就诊上下文、模板和数字材料的正式版本采用不可变版本或快照；更正只能追加新事实。
9. **P08-RULE-009**：同一对象可以有生命周期、质量、可用性、交接、验证和投递等不同维度；不得将这些维度压成一个万能状态。
10. **P08-RULE-010**：流程失败只阻断受影响对象或责任边界；已形成事实不得因下游失败无痕回滚，未受影响的对象继续按其自身状态机运行。
11. **P08-RULE-011**：禁止从终态回到历史中间态；重试、复测、补切、重扫、补发、重签和恢复均形成新任务、新尝试、新版本或新事实。
12. **P08-RULE-012**：不建立状态的对象必须明确采用不可变事实、不可变版本/快照、质量/可用性维度、派生展示状态、上级对象控制或医院配置结论。
13. **P08-RULE-013**：实际玻片可来自蜡块、细胞学标本、细胞学制备物或外部材料；状态机不得将蜡块设为唯一来源。
14. **P08-RULE-014**：细胞学制备记录和条件性制备物分开；瞬时中间物不因流程完整性被虚构为稳定对象。
15. **P08-RULE-015**：细胞学充分性、筛查、复核、诊断和签发分别表达责任与事实；任何一项不能覆盖其他记录。
16. **P08-RULE-016**：分子任务、材料、运行、质控、设备原始结果、有效结果、医学判读和报告版本必须分别保留身份和历史。
17. **P08-RULE-017**：本地事实、出站事件、投递尝试、外部业务状态和对账差异分开；外部结果不得伪装成本地执行事实。
18. **P08-RULE-018**：报告只能通过补充、更正、撤回、重新签发或新综合报告改变；组成报告不被综合报告覆盖。
19. **P08-RULE-019**：系统或设备可靠获得的信息不要求人工重复录入；人工确认只产生责任确认或审核事实。
20. **P08-RULE-020**：医院配置可以改变角色范围、复核范围、启用能力、编号展示、提醒和通知策略，但不得改变身份、来源、责任、历史保护和安全守卫。
21. **P08-RULE-021**：正式状态机编号为 `P08-SM-XXX`，状态为 `P08-SM-XXX-ST-##`，转换为 `P08-SM-XXX-TR-##`，维度为 `P08-SM-XXX-DIM-##`。
22. **P08-RULE-022**：异常入口只在状态机中表达触发条件、影响对象、阻断范围、处理方向和恢复输入；完整异常处置仍以 P07 为准。
23. **P08-RULE-023**：P08 输出供 P09、P10、P11、P12、P14、P24 和 P25 使用，但不提前定义需求、架构、事务、数据结构、接口字段、权限实现、页面或测试实现。

## 2. 状态和维度的写法

状态名称必须是对象可核验的业务结论，例如“已接收”“待核对”“已签发”。“处理中”“异常”“待处理”等词只有在注明对象、触发事实和离开守卫时才可使用。质量和可用性维度可以标记“不合格”“隔离”或“不可用”，但不得改变来源对象的身份和历史。

每张转换表至少列出：转换编号、源状态、事件、前置条件、守卫、目标状态、责任角色、形成事实、失败/异常、重试方向、审计要求和 P07 异常编号。转换失败时记录异常事实，不能假装没有发生。

## 3. P08 边界

本阶段完成对象状态定义、转换守卫、异常影响、恢复方向、跨对象协调和追溯。P09 负责把这些结论转为需求，P10 负责技术一致性与补偿，P11 负责持久化模型，P12 负责接口契约，P14 负责权限细化，P24 负责页面，P25 负责测试验证。
