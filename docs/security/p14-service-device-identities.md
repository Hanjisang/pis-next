# P14 服务、设备与外部系统身份模型

文档状态：P14 已设计

## 1. 主体边界

服务身份、后台任务身份、设备身份和外部系统身份均属于非人工主体。它们可以成为来源和执行者，但不能成为临床责任人。非人工身份必须有拥有组织、用途、来源、有效期、撤销状态、调用范围和审计关联。

## 2. 服务身份允许能力

服务身份的允许能力共 5 类：

1. 接收 P12-HIF-001 至 P12-HIF-003 的外部原始事实并保存来源摘要；
2. 提交设备/接口产生的原始事实、文件元数据和事件载荷；
3. 执行已授权的后台任务、重试、补偿、文件校验和对账；
4. 生成传输文件、报告呈现文件或技术处理文件，但不决定医学内容；
5. 投递已形成的 P10/P12 业务事件并记录投递结果。

服务身份允许能力数量：5。每项能力仍受对象、任务、范围、版本、幂等和审计守卫约束。

## 3. 服务身份禁止能力

服务身份禁止 5 类能力：医学诊断或判读、最终结果确认、受控报告责任、销毁/恢复/权限批准、独立第二人复核。服务调用失败时只能形成失败、待处理或补偿事实，不能伪造人工结果。

## 4. 设备身份允许能力

设备身份的允许能力共 3 类：任务接收/状态回执、原始载荷或运行事实提交、设备质量/文件完整性数据回传。设备能力必须绑定设备任务、设备批次、材料/样本身份和尝试版本。

设备身份允许能力数量：3。

## 5. 设备身份禁止能力

该类非人工主体禁止医学判读、诊断确认、受控报告责任和独立复核，共 4 类。设备运行成功不等于临床结果有效；P12-API-029、P12-API-030 和 P12-HIF-008 至 P12-HIF-010 必须保持原始结果、质控、有效结果和医学判读分离。

## 6. 外部系统身份

外部系统身份只通过 12 个正式医院接口使用相应输入/输出能力。外部系统可以提交申请、医嘱关联、外部结果、设备回执和外送交换，也可以接收已形成的状态、进度、报告版本、文件引用和对账通知；它不能直接改变核心业务表或取得本地医学责任。

## 7. 服务/设备审计

每个非人工调用必须记录主体标识、拥有组织、调用来源、任务/设备/接口、原始载荷摘要、对象范围、处理结果、错误或补偿方向和关联人工责任（如存在）。原始来源和人工确认不得互相覆盖。
