# P14 角色模型

文档状态：P14 已设计

## 1. 角色口径

正式角色来源为 `docs/project/user-roles.md` 的 `ROLE-PIS-001` 至 `ROLE-PIS-021`，共 21 个业务角色。P14 不把医院岗位名称直接当作授权结论，也不新增跨业务的泛化角色。角色只聚合候选能力，实际生效仍需资格、组织、数据范围、任务责任、对象状态和高风险规则。

## 3. 角色组合与限制

同一人工主体可以在医院授权下承载多个非冲突角色，但每次高风险动作按职责分离重新判断。以下组合默认不能由同一责任链无痕完成：

- 诊断形成与最终独立复核；
- 报告起草与受控签发；
- 纠错申请与纠错批准；
- 档案销毁申请、批准与见证；
- 权限/范围请求与批准；
- 接口重放申请与审计确认；
- 质量整改责任与高等级事件最终关闭。

医院规模不足时，使用显式例外、批准、时间范围、原因和审计，不能用角色合并消除责任关系。

## 4. 系统管理员边界

`ROLE-PIS-014` 仅代表技术与配置治理。它可以管理主体映射、能力配置、组织关系和运行参数，但不自动获得任何取材、技术执行、医学判读、诊断、报告签发、销毁批准或独立复核权限。高风险权限配置本身仍需审批与审计。
