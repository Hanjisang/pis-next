# P14 授权决策模型

文档状态：P14 已设计

## 1. 决策输入

一次授权决策固定检查 18 类输入：

| 编号 | 输入 | 判定内容 |
|---:|---|---|
| 1 | 主体身份 | 主体存在、状态和唯一引用 |
| 2 | 主体类型 | 人工、服务、任务、设备或外部系统限制 |
| 3 | 认证强度 | 当前认证是否满足动作风险 |
| 4 | 角色 | 业务角色与能力候选 |
| 5 | 资格 | 岗位、专业、方法或复核资格 |
| 6 | 组织关系 | 医院、院区、科室、工作组和外部机构 |
| 7 | 数据范围 | 目标对象、病例、队列、文件和用途 |
| 8 | 目标资源 | 对象、聚合、来源、文件或治理记录 |
| 9 | 业务动作 | `P14-PERM` 中的稳定动作 |
| 10 | 对象状态 | P08 当前状态、目标状态和非法转换 |
| 11 | 对象来源与链路 | 标本、材料、结果、报告和文件来源 |
| 12 | 任务责任 | 分配、接管、交接、批准或复核责任 |
| 13 | 代理上下文 | 授权人、被代理人、范围和有效期 |
| 14 | 临时/紧急上下文 | 原因、批准、起止和事后复核要求 |
| 15 | 并发版本 | 预期版本、当前版本和重复意图 |
| 16 | 患者安全守卫 | 关键错误、隔离、冻结、质量和影响范围 |
| 17 | 职责分离 | 执行、批准、复核和审计冲突 |
| 18 | 调用来源 | 内部业务命令、查询、文件、事件或 12 个接口 |

## 2. 决策结果

决策结果共 7 类：

1. 允许形成业务事实；
2. 拒绝并返回稳定错误和处理方向；
3. 需要增强认证/重新认证；
4. 需要独立第二人复核；
5. 需要批准或治理授权；
6. 需要接管/交接任务责任；
7. 转人工裁决、隔离或补偿队列。

中间结果不能被调用方解释为允许；只有所有必需守卫完成后才形成最终允许。

## 3. 决策顺序与解释

先判断主体和调用来源，再判断动作、资格、范围、责任、对象/状态、风险和职责分离，最后处理并发和审计。授权解释必须列出拒绝/中间结果原因及缺失项，但不得向无权主体泄露患者正文、原始载荷或其他敏感数据。

## 4. 重试与缓存

授权结果不能跨越主体状态、角色/范围变更、代理失效、对象状态变化、版本变化、增强认证超时或紧急授权关闭继续使用。技术重试必须重新获取授权上下文；业务冲突、患者安全阻断、报告版本冲突、销毁和恢复失败进入人工处理。
