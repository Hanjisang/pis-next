# P14 主体与身份模型

文档状态：P14 已设计

## 1. 模型结论

P14 形成 5 类正式主体类型：人工主体、服务身份、后台任务身份、设备身份和外部系统身份。人工主体有 21 个 PIS 业务角色来源；服务侧分为 2 个受限子类型；设备和外部系统各为 1 个主体类型。`ROLE-EXT-001` 至 `ROLE-EXT-003` 是外部协作方的业务角色描述，不自动成为 PIS 核心工作站用户。

主体类型不是权限。主体必须经过认证或来源校验，再将有效角色、资格、组织、数据范围、责任和授权上下文组合为一次决策。

## 2. 正式主体类型

| 编号 | 主体类型 | 数量口径 | 可承担的责任 | 明确限制 |
|---|---|---:|---|---|
| P14-SUB-001 | 人工业务主体 | 21 个业务角色来源 | 仅在具备相应资格、责任、范围和状态守卫时形成业务事实 | 不得借用其他主体完成无法追溯的签名或复核 |
| P14-SUB-002 | 服务身份 | 1 类 | 消息接收、原始事实提交、文件生成、事件投递 | 不承担任何医学责任、批准或独立复核 |
| P14-SUB-003 | 后台任务身份 | 1 类 | 重试、补偿、索引/文件协调、对账任务 | 不改变业务责任，不将自动执行伪装为人工责任 |
| P14-SUB-004 | 设备身份 | 1 类 | 设备执行回执、原始载荷、质量数据和任务状态回传 | 不承担任何医学责任、批准或独立复核 |
| P14-SUB-005 | 外部系统身份 | 1 类 | 仅经 12 个正式医院接口交换外部事实 | 不直接写核心事实，不取得本地临床责任 |

## 4. 身份、责任与关系分离

同一次操作至少保留以下关系：

| 关系 | 说明 |
|---|---|
| 认证主体 | 本次请求通过认证或来源校验的身份 |
| 实际操作者 | 真正发起业务动作的人工、服务或设备主体 |
| 业务责任人 | 对业务事实承担岗位/任务责任的人 |
| 代理责任人 | 被正式代理的原责任人，不替代实际操作者 |
| 批准人 | 对高风险授权或治理动作作出批准的人 |
| 独立复核人 | 对指定事实或风险独立确认的人 |
| 服务/设备来源 | 产生原始载荷或执行回执的非人工主体 |
| 外部来源 | 经正式接口进入的医院或外送机构事实来源 |

任何关系缺少身份、时间、范围或来源时，不能形成可放行的授权上下文。

## 5. 资格与主体状态

人工主体的资格、执业/岗位状态、组织任职和授权期限是决策输入，不在 P14 假设具体医院证照字段。主体停用、资格过期、组织关系结束、代理撤销或紧急授权关闭后，不能继续发起新高风险动作；历史事实仍保留原主体引用。

服务、任务、设备和外部系统身份同样需要启用、撤销、轮换和来源关联，但它们不能通过主体类型转换获得人工医学责任。
