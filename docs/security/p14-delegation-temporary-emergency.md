# P14 代理、临时与紧急授权模型

文档状态：P14 已设计

## 1. 授权关系类型

| 编号 | 类型 | 适用范围 | 关键限制 |
|---|---|---|---|
| P14-DEL-001 | 角色代理 | 岗位临时替班或明确的非高风险职责 | 不自动包含高风险、医学签发或独立复核 |
| P14-DEL-002 | 任务代理 | 指定病例、任务、材料或报告上下文 | 对象、动作和时间必须逐项限定 |
| P14-DEL-003 | 查询/会诊代理 | 指定摘要、依据或文件引用 | 不能提交、确认、签发或批准 |
| P14-DEL-004 | 临时授权 | 预先批准的短期职责覆盖 | 到期自动失效，不能无限续期 |
| P14-DEL-005 | 紧急授权 | 患者安全或业务连续性风险 | 强认证、最小对象范围、事后独立复核 |

服务和设备身份的执行能力属于主体类型约束，不通过代理获得人工医学责任。

## 2. 代理关系字段

每一条代理关系必须能回答：谁授权、谁被授权、谁实际操作、代理哪一类角色/任务、哪些能力和动作、哪些对象/数据、适用病理类型、起始和失效时间、原因、批准人、是否需要复核、撤销原因、使用次数/使用审计和关闭证据。字段语义由 P14 定义，物理存储留待后续数据阶段。

## 3. 生效和撤销

代理必须在生效时间后才可使用；授权人失效、被代理人失效、组织关系结束、任务结束、对象被隔离、授权撤销或失效时间到达时立即停止新动作。撤销不抹除已发生的使用记录；已形成事实按原授权上下文保留。

## 4. 临时授权

临时授权必须：

- 有明确责任缺口和业务原因；
- 指向一个或多个具体能力、任务或对象范围；
- 指定起止时间，且结束时间不可为空；
- 由不承担同一执行责任的批准人批准；
- 对报告、医学判读、销毁、恢复开放、权限变更等高风险动作单独判断；
- 失效后拒绝新操作，并产生到期审计。

临时授权不能改变历史事实、降低患者安全守卫或赋予服务/设备身份人工责任。

## 5. 紧急授权

紧急授权仅在明确的患者安全风险、关键业务中断或恢复风险下启用。启用时记录风险、受影响对象、允许动作、实际操作者、强认证结果、授权人/批准人、起止时间和预计影响；每次使用都形成单独审计。紧急授权结束后必须产生事后复核任务，确认使用是否必要、范围是否超出、患者安全守卫是否保持、事实是否完整以及是否需要补偿或纠错。

紧急授权不能用于常规排班、方便查询、绕过资格、替代报告签发人或替代独立复核人。

## 6. 代理与责任

代理只改变“可代为执行的范围”，不改变实际操作者、被代理责任人、批准人和复核人的身份。报告签发、诊断确认、医学判读、质量关闭、销毁批准和恢复放行的责任关系必须单独记录。
