# P16 API、安全与数据范围映射

## 1. 命令映射

| P16命令 | P12依据 | 权限/责任 | 结果 |
|---|---|---|---|
| 建立取材批次 | P12-API-050队列责任 | P14-PERM-050 / 取材任务 | 批次计划 |
| 分配/接管/交接任务 | P14-TASK-001/002/003 | P14-PERM-050 | 唯一责任主体 |
| 开始/暂停/恢复/完成/取消批次 | P12-API-013边界 | P14-PERM-013 | 状态历史和审计 |
| 记录取材和更正 | P12-API-013 | P14-PERM-013 | 追加取材记录 |
| 建立计划蜡块、分配取样 | P12-API-014 | P14-PERM-014 | 来源明确的计划身份 |
| 生成标签 | P12-API-014标签边界 | P14-PERM-014 | 版本化标签快照 |
| 提交/记录打印结果 | P12-API-014标签边界 | P14-PERM-014 | 请求和尝试历史 |
| 重打/作废标签 | P14高风险控制 | P14-PERM-014并要求理由 | 新尝试/作废事实 |

## 2. 查询映射

待取材队列和我的任务复用 P12-API-050；来源链、批次详情、记录、取样、计划蜡块、标签状态和打印历史复用 P12-API-048/P12-API-044 的查询原则。所有查询强制带 `organization_reference`、任务范围、状态过滤、稳定排序和有限分页；不提供任意SQL导出。

## 3. 授权守卫

所有 P16 写命令调用 P15 `ActorContext`/授权服务，并同时检查：运行环境、权限、医院/科室范围、任务责任、标本状态、聚合版本和必要资格。接管使用数据库条件更新，竞争失败者得到版本冲突，不产生第二个有效责任人。查询不因前端隐藏按钮而获得授权。

患者/病例/标本身份摘要不匹配时返回患者安全错误并记录异常和审计；不会允许普通确认绕过。错误响应只返回错误码、相关标识和安全消息，不泄漏 SQL、表名、堆栈、完整患者标识或打印机内部信息。

## 4. 幂等与事件

每个写命令请求体接受幂等键；需要修改聚合的命令同时接受预期版本。批次建立、标签生成和打印请求实际持久化幂等结果；同键同载荷返回权威结果，同键不同载荷拒绝；其余命令仍由版本条件和唯一约束阻断重复事实。P16 事件沿用 P10/P12 事件标识：取材批次建立、任务接管、状态变更、取材记录、组织取样、计划蜡块编号、标签生成、打印请求、标签作废和取材完成，事件写入现有 outbox。
