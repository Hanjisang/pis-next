# P19 领域与数据设计

## 1. 聚合边界

`p19_diagnosis_task` 拥有诊断任务、责任历史、工作草稿、诊断意见、意见版本和复诊记录；`p19_report` 拥有报告、报告内容版本、章节版本、审核、签发事实和修订关系。P19 通过外键引用既有病例及 P18 技术结果边界，不重复拥有病例、标本、蜡块、切片或技术医嘱主数据。

## 2. 版本与快照

诊断草稿可修改，正式诊断意见提交后形成不可变版本。报告草稿独立于诊断意见；报告内容版本是完整业务快照，包含患者、就诊、病例、标本材料、诊断版本、技术结果引用和结构化章节。签发后的内容版本只读，补充、更正、撤回和重新签发通过新记录与关系链表达。

## 3. 迁移与约束

Flyway V8 创建 20 张 P19 领域/历史/关系表（含 1 张幂等表）；Flyway V9 增加独立 `p19_report_draft` 报告草稿表并补充当前有效报告版本外键，共 21 张 P19 表。所有核心对象使用不可变 UUID 内部 ID 与独立业务编号；版本序列由报告行内原子递增分配，不使用 `SELECT MAX + 1`，也不由前端计算。

表级约束包含主键、外键、唯一约束、状态 CHECK 和队列索引。关键命令在应用服务校验权限、数据范围、任务责任、乐观锁和幂等键，并在同一事务中写入事实、审计和 outbox。

## 4. 禁止范围

不使用 EAV、通用多态外键、无约束 JSON 承载核心业务、级联物理删除或覆盖已签发历史；不创建数字切片、AI、冰冻执行、PDF 生产、CA/电子签章供应商、医院回传或生产部署业务表。
