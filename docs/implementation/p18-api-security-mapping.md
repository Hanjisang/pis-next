# P18 API、安全与责任映射

## 1. API 映射

| 能力 | Controller 路径 | P12/权限映射 |
|---|---|---|
| 建立/追加技术医嘱项目 | `/api/p18/orders` | P12-API-015 / P14-PERM-015 |
| 计划产物 | `/api/p18/projects/{id}/planned-outputs` | P12-API-016 / P14-PERM-016 |
| 目标绑定/更正 | `/api/p18/projects/{id}/target` | P14-PERM-015，治理审计 |
| 提交/审核 | `/api/p18/orders/{id}/submit`、`/review` | P14-PERM-015 |
| 受理/分配/接管 | `/receive`、`/assign`、`/takeover` | P14-PERM-050 |
| 执行交接/结果引用 | `/execution-handoff`、`/result-reference` | P12-API-017 / P14-PERM-017 |
| 完成/取消 | `/close`、`/cancel` | P14-PERM-015/017，审计 |

P18 复用 P12 API 能力标识和 P14 权限标识，不扩展正式医院或设备协议。响应包含业务身份、状态维度、并发版本、重复标识和计划产物，不返回未经规范化的临床结果。

## 2. 授权执行点

所有写命令由后端应用服务授权。创建/审核/取消需要 `P14-PERM-015`，计划修改需要 `P14-PERM-016`，执行交接/结果引用需要 `P14-PERM-017`，受理/分配/接管需要 `P14-PERM-050`。应用服务拒绝 `DEVICE`/`SERVICE` 主体承担人工开立、审核和执行责任；任务责任代码必须是 `P18-TECHNICAL-ORDER`。

查询按病例和组织范围过滤；乐观锁拒绝陈旧写入；每个关键动作记录操作者、主体、目标、权限、原因、版本、幂等键和时间。审计与 outbox 在业务事务内提交。

## 3. 错误与禁止事项

复用 P12 稳定错误语义：缺少必填值、目标不存在/跨病例/无效、状态不允许、权限不足、责任主体不允许、幂等冲突和版本冲突。不存在通用 `setStatus`、万能 CRUD、设备直写核心表、服务主体替代临床责任或前端直接改状态。
