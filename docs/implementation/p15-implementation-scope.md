# P15 登记与标本接收实现范围

文档状态：实现设计；日期：2026-08-06

## 1. 正式边界

P15 的正式名称为“登记与标本接收”。本阶段实现一个可运行的纵向切片：合成外部申请入站或手工申请 → 申请幂等与本地身份 → 病例建立和病理类型 → 业务编号 → 预计标本与容器 → 条码扫码接收 → 身份/来源/数量核对 → 责任交接、隔离/退回异常 → 受控查询、审计和发件箱事件。

直接落地的正式需求为：

| 类别 | 正式编号 | 本阶段实现责任 |
|---|---|---|
| 申请、病例和接收 | P09-REQ-0001–0006、0008–0015 | 外部原始事实、手工申请、外部申请标识、幂等、患者/就诊上下文、申请/病例分离、类型和编号、预计标本、逐标本核对、交接、部分独立推进、下游事实保护边界 |
| 受控安全与审计 | P09-REQ-0016、0018、0020、0070、0073、0074、0076、0080、0081、0082 | P14 权限入口、服务端身份、范围求交、追加审计、原始事实/快照保护、幂等和版本证据 |

上述需求的正向/负向 AC-01/AC-02 由后端领域测试、API 测试、JDBC 集成测试和前端工作台验收承载。未实现的需求保留在后续阶段，不在本阶段用占位代码伪装完成。

## 2. 场景、流程和状态机

实现覆盖正式场景 `SCN-PIS-001/002/003/004/005/010/011/012/013`，以及对应的 P06 流程 `P06-PROC-001/002/003` 的正常步骤和 P07 输入：来源/身份不一致、重复/乱序、数量差异、部分到达、交接不完整、隔离和退回。取消/终止和受控纠错只保留应用入口和历史保护边界，具体治理审批不提前实现。

实现只使用正式状态机：

- `P08-SM-001` 申请接收生命周期：`待接收 → 待核对 → 已建立`；重复归并、取消和拒绝是受控事实，不把外部状态直接覆盖本地状态。
- `P08-SM-002` 病例建立生命周期：`待建立 → 待生效 → 已建立`；病例身份、申请身份和快照分离。
- `P08-SM-003` 标本接收生命周期：`待接收 → 待核对 → 已接收`；异常方向为拒收、让步接收待复核或隔离。

禁止从已建立/已接收或已拒收无依据回到初始状态，禁止用病例状态覆盖标本事实，禁止物理删除医疗记录，禁止把登记、标签或预计到达当作实际接收。

## 3. 明确排除

P15 不实现取材、蜡块、脱水、包埋、切片、染色、冰冻制备/诊断、细胞制备/筛查、分子检测、外送执行、诊断、报告、数字切片、收费、医院生产接口配置、生产 IAM、权限管理页面和生产部署。下游仅通过既有正式对象、事件和查询契约保留边界。

## 4. 工程边界

继续使用模块化单体、Java 21、Spring Boot 4.1.0、Spring Modulith 2.1.0、Spring JDBC、Flyway、Vue 3.5.40、Vite 8.1、Node 24.x 和 PostgreSQL 18.4。后端不使用 JPA/Hibernate/MyBatis/Lombok，不建立通用 CRUD 控制器，不提供任意状态更新接口。

实现按 P10 所有权放置：申请/病例写入在 `accession`，标本/容器/接收在 `specimen`，授权、责任、审计和发件箱证据在 `security`；模块之间只通过应用端口协作。数据只使用合成值。
