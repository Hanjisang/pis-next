# P17 包埋与实际蜡块形成设计

包埋任务只能由已人工确认且 `can_enter_embedding=true` 的组织处理结果建立。任务、责任接管、执行开始、要求快照和完成事实各自有版本和状态；未完成包埋不改变 `physical_formed_at`，也不把计划蜡块当作实际蜡块。

首次完成包埋时，事务按以下顺序校验：包埋责任、要求快照、来源蜡块范围、`P08-SM-004-ST-02`、物理形成时间为空、处理结果可准入、任务并发版本和蜡块并发版本。锁定同一蜡块后写入包埋事实、实际形成事实，再将蜡块推进至 `P08-SM-004-ST-03`。

包埋返工创建新尝试，使用 `rework_of_formation_id` 指向当前有效形成事实；旧事实改为 superseded，新事实使用递增形成版本并写入替代关系。作废只把形成事实标为无效并将蜡块置为 `P08-SM-004-ST-04`，不删除任何历史。

实际形成事实沿用 P16 蜡块业务编号 `inherited_block_no`，不产生第二个蜡块主表。此选择与 `OBJ-004`、`AGG-004` 和 P08 蜡块生命周期保持一致。
