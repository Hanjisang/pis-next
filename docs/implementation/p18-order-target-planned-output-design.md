# P18 医嘱、目标与计划产物设计

## 1. 医嘱与项目

医嘱只表达病例级技术请求；每个项目表达一个独立技术动作。多个项目可以同时处于不同的审核、受理、执行交接和结果状态。项目类型与项目配置版本绑定，历史医嘱保存配置快照，配置后续变化不重写历史。

项目类型到业务含义的映射如下：

| 项目类型 | P18 含义 | 计划产物 | 实际执行 |
|---|---|---|---|
| `DEEP_SECTION` | 深切请求 | 计划玻片 | 后续阶段 |
| `RECUT` | 重切请求 | 计划玻片 | 后续阶段 |
| `WHITE_SLIDE` | 白片请求 | 计划玻片 | 后续阶段 |
| `IHC` | 免疫组化请求 | 计划玻片/项目染色引用 | 后续阶段 |
| `SPECIAL_STAIN` | 特殊染色请求 | 计划玻片/项目染色引用 | 后续阶段 |

## 2. 目标链

当前 P18 只允许 `ACTUAL_BLOCK` 目标，并要求目标关联病例和 P17 实际蜡块形成事实。查询会再次验证病例一致性、形成事实当前有效性、蜡块生命周期和阻断条件；前端输入不能绕过后端校验。目标更正先追加旧目标历史，再写入新目标和审计事实。

目标链：

```text
病例 → P16 计划蜡块 → P17 组织处理/包埋 → P17 实际蜡块形成事实
                                                    ↓
                                          P18 技术医嘱项目目标
```

## 3. 计划与实际边界

`p18_planned_output` 记录序号、产物类型、用途、计划数量、染色项目引用、计划标签数量和执行备注。P18 不插入实际玻片、不推进实际玻片状态、不写设备执行结果；规范化结果引用只作为后续执行边界的回收入口，必须携带结果类型、身份、摘要、环境和说明。
