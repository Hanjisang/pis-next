# P18 生命周期与更正设计

## 1. 状态维度

P18 保留 P08 技术任务维度：`PENDING_SUBMISSION`、`PENDING_AUTHORIZATION`、`EXECUTED`、`CANCELLED`。实现同时维护项目审核、受理、执行交接和结果维度，避免一个状态字段覆盖全部责任和医学事实。医嘱状态由项目状态聚合计算。

核心命令边界：

```text
开立 → 提交 → 审核通过 → 受理 → 分配/接管 → 执行责任交接
                                      ├─ 结果引用 → 完成
                                      └─ 取消
```

每个命令都在应用服务执行身份、权限、病例/组织范围、任务责任、状态前置条件和预期版本校验；Controller 不直接修改状态。

## 2. 更正与异常

- 目标更正：禁止静默覆盖，写入目标历史和变更记录；
- 追加项目：建立新项目，不覆盖既有项目；
- 计划产物追加：追加新的序号记录；
- 责任变更/接管：保留原责任、现责任、原因和操作者；
- 取消：追加取消事实，保留原项目和原状态历史；
- 执行责任交接后禁止普通目标修改；
- 无规范化结果引用不得完成项目；
- 并发版本冲突返回稳定错误，不覆盖他人修改；
- 同幂等键不同载荷拒绝，失败事务不留下半成品。

## 3. 事务与证据

每个写命令在一个事务内写业务事实、状态历史、审计记录和 outbox 记录。状态历史和更正历史只追加；outbox 使用 P12 命令契约标识承载事实投递。P18 未新增 P10 架构事件，目标更正/取消治理引用使用既有 P12-EVC-021；实际执行和结果入口仍不等于实际玻片或染色事实。
