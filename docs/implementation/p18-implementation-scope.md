# P18 技术医嘱实现范围

## 1. 阶段边界

P18 实现 `MASTER_PLAN.md` 中“技术医嘱”阶段：围绕深切、重切、白片、IHC、特殊染色等技术项目建立可追溯的医嘱及管理边界。P18 的交付对象是技术需求、项目目标、计划产物、责任交接和下游结果引用，不是实际制片或染色执行。

正式输入：P08 技术任务状态机、P11 材料与技术数据字典、P12 命令/API/事件契约、P14 权限与责任模型、P17 实际蜡块形成事实及 P18 附件规则 P18-001～P18-021。

## 2. 本阶段实现

- 一个技术医嘱可包含多个相互独立推进的技术项目；
- 项目类型：`DEEP_SECTION`、`RECUT`、`WHITE_SLIDE`、`IHC`、`SPECIAL_STAIN`；
- 项目目标绑定当前病例内有效的 P17 实际蜡块形成事实；
- 项目配置和版本快照；计划玻片/计划标签数量及用途；
- 开立、提交、审核、受理、分配、接管、执行责任交接、结果引用、完成、取消；
- 目标更正、追加项目、计划产物追加、责任变更和取消历史；
- 后端权限、数据范围、任务责任、幂等键、乐观锁、审计和 outbox；
- JDBC/PostgreSQL 参考实现、Flyway V7、Vue 工作台、Docker/Compose 烟测脚本和回归测试。

## 3. 明确排除

P18 不实现实际切片形成、实际深切/重切、IHC 或特殊染色执行、染色/封片、设备运行时、技术质控结果、数字切片、诊断、报告、冰冻和生产医院/设备协议。P18 不创建实际玻片、染色执行、诊断或报告表，也不新增微服务。

## 4. 环境与数据假设

实现使用合成/本地开发数据和 P17 已形成的合成实际蜡块。五条项目配置种子使用 `P18-SYNTHETIC-*` 与 `SYNTHETIC-1`，不是医院正式编码。PostgreSQL 18.4 是参考数据库；正式医院配置、设备协议和临床生产部署仍待业务/部署阶段确认。

## 5. 交付清单

- 后端：P18 领域、JDBC、应用服务、Controller、Flyway V7；
- 前端：P18 技术医嘱工作台及 API 类型；
- 验证：领域、应用、Web、PostgreSQL、前端组件和全栈 smoke；
- 文档：数据、目标/计划产物、生命周期、API/安全、前端、测试、追溯和关闭审查。
