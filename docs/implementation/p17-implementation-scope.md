# P17 组织处理与包埋实现范围

## 正式范围

P17 实现 `P09-REQ-0023`（组织处理与包埋完成）及其 AC-01 正向验收和 AC-02 负向验收；复用 P09-REQ-0022 的蜡块业务记录和编号边界。对应场景为 `SCN-PIS-030` 建立/执行脱水任务、`SCN-PIS-031` 完成组织处理、`SCN-PIS-032` 完成包埋并形成蜡块。对应流程为 `P06-PROC-007`，覆盖 S01–S06、D01–D03 和 E01–E03。

异常映射为 `P07-EXC-019` 批次局部失败（SEV-3）、`P07-EXC-020` 处理/包埋失败及返工（SEV-3）、`P07-EXC-021` 来源或编号冲突（SEV-1）。实现保留异常、影响判定、恢复和重处理关系，不覆盖原事实。

| 正式输入 | P17 落地 |
|---|---|
| 对象 | `OBJ-004` 蜡块业务记录、`OBJ-016` 技术执行记录、`OBJ-024` 组织处理批次、`OBJ-027` 异常记录 |
| 可选边界 | `OBJ-039` 组织盒、`OBJ-040` 设备任务、`OBJ-041` 设备运行批次由已有身份/事实字段承接，不引入厂商协议 |
| 聚合 | `AGG-004` 蜡块、`AGG-007` 技术医嘱/执行协调 |
| 状态机 | 复用 `P08-SM-004` 蜡块生命周期；执行任务采用 P17 独立责任状态，不新增正式 P08 状态机 |
| 权限 | `P14-PERM-050` 技术工作队列、`P14-PERM-014` 蜡块/包埋责任、`P14-PERM-029` 设备及原始执行事实 |
| 责任 | 复用 `P14-TASK-001`–`P14-TASK-006` 的分配、接管、执行、交接和审计原则 |
| 数据范围 | 仅允许当前主体的 `LOCAL_HOSPITAL` 组织范围；查询和写入均带组织条件 |

## 已实现能力

1. 处理任务、责任接管、处理批次、程序/版本快照、程序步骤和人工/设备执行模式。
2. 运行、步骤、原始设备结果、人工确认的有效结果及其幂等关系。
3. 批次部分成功、失败、中断、成员影响判定、恢复和重处理任务。
4. 包埋任务、责任接管、包埋要求快照、方向参考、包埋事实和实际蜡块形成事实。
5. 首次形成、返工替代、作废、版本链、`tissue_block.physical_formed_at` 和 `P08-SM-004-ST-03` 的事务一致性。
6. JDBC、Flyway、29 个 P17 Web 路由、Vue 工作台、审计、状态历史、outbox 和幂等复用。

## 明确排除

本阶段不实现后续切片执行、染色、封片、诊断、报告、数字切片、库存、生产部署、真实设备 SDK、厂商协议或真实患者数据。后续阶段不得把 P17 的合成程序种子当作临床程序。
