# P19 诊断与报告实现范围

状态：实现中，待最终关闭审查。日期：2026-08-06。

## 1. 正式边界

P19 只实现诊断任务、责任接管、诊断草稿、初诊意见版本、复诊/复核留痕、报告草稿、结构化报告内容版本、独立审核、增强认证签发、补充、更正、撤回和重新签发的本地纵向切片。P15～P18 仍是上游权威来源；P19 只引用 P18 技术项目/结果身份，不复制或修改 P18 事实。

P19 不实现医院报告回传、患者端、数字切片、AI、冰冻、生产 PDF、电子签章厂商、生产部署或新的微服务。

## 2. 依据与映射

| 领域 | 正式依据 | 本实现 |

| 数据 | P11 诊断/报告字典 | V8 业务表、版本约束、追加历史、幂等表 |

## 3. 交付状态

- 实现：P19 后端 JDBC/Flyway、P19 前端工作台、P19 API、审计和 outbox 接入、分层测试、脚本和实现文档。
- 复用：病例、患者/就诊、标本、材料、P18 技术医嘱、P14 权限、P10/P12 审计与 outbox。
- 仅边界：正式认证供应商、外部回传、PDF/打印、数字切片和 AI。
- 后续：外部报告交付、医院对账和生产增强认证适配。

## 4. 验收重点

正常链为诊断责任 → 草稿 → 初诊版本 → 报告完整快照 → 独立审核 → 增强认证签发。异常链覆盖无责任、同主体复核、版本冲突、阻断技术医嘱、签后修改和撤回历史保留。所有结论以实际测试和 Docker/Compose 验证为准。
