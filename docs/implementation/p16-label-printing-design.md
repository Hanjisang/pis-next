# P16 标签与打印设计

## 1. 身份分层

内部 UUID 是稳定身份；`block_no`/`tissue_box_no` 是业务编号；`label_identity` 是标签业务身份；`label_print_request` 是一次打印请求；`label_print_attempt` 是请求中的一次尝试。任何重打都不新建蜡块，也不复用旧打印尝试。

## 2. 内容快照

标签生成时冻结目标对象 ID、目标对象版本、标签版本、模板逻辑版本、生成主体/时间、病例号、蜡块号、最小患者核对摘要、取材序号、病理类型、来源摘要和条码载荷。快照只包含完成标签核对所需的最小信息，不包含完整证件号、电话、地址、诊断或原始入站报文。

## 3. 条码和渲染

正式医院条码制式和打印机厂商协议尚未锁定。P16 提供 `BarcodePayload` 参考载荷和浏览器可预览 HTML/CSS；明确标注 DEV/reference，不宣称正式医疗条码标准。标签生成、预览、提交、打印结果确认和附件确认是不同事实。

参考适配器只返回 `GENERATED` 或 `SUBMITTED`；它不能确认物理打印机成功，因此不写入 `PRINT_CONFIRMED`，也不把 `window.print()` 当成打印成功。

## 4. 重打与作废

重打必须提供原因、原标签身份/版本和原打印尝试，创建新的打印请求和尝试，并记录操作者、时间、审计和是否作废旧标签。标签作废追加状态事实；原内容和打印历史保留。重打权限不自动等同于普通查询权限。
