# P18 前端技术医嘱工作流

## 1. 工作台

`P18TechnicalOrderWorkbench.vue` 提供合成开发数据下的技术医嘱开立和提交入口：输入病例内部 ID、P17 实际蜡块形成事实 ID，选择深切/重切/白片/IHC/特殊染色，设置优先级、用途、原因、计划数量和计划标签数量，随后刷新医嘱队列。

页面明确展示“配置快照、目标、计划产物、责任链”和“计划不等于实际”。提交后只显示后端返回的状态/并发版本，不乐观伪造审核、受理、执行、实际玻片或染色结果。按钮禁用只用于交互提示，真正权限和范围校验由后端执行。

## 2. API 边界

`frontend/src/api.ts` 使用 `/api/p18`，统一 JSON 错误处理，并为医嘱、项目、计划产物和状态维度提供类型。组件通过 `fetch` 调用正式 Controller，不在浏览器计算或写入业务状态。输入控件支持键盘 Enter 触发刷新/开立；扫码枪可将条码/ID作为普通输入送入后端校验。

## 3. 范围保护

页面不提供实际制片、染色、封片、设备控制、技术质控、数字扫描、诊断或报告入口。所有演示内容均为合成/本地数据，组件文案明确 P18 的下游边界。
