# P16 取材与蜡块实现范围

## 1. 基线与归属

本阶段实现 `P16-GROSSING-BLOCK-LABELING-FINAL`，归属已经存在的 `technical` Spring Modulith 模块。P15 的病例、标本、容器、接收事实、审计和 outbox 是权威来源；P16 不建立重复标本主记录。

P16 的正式输出是：取材批次、取材记录、组织取样、计划蜡块/包埋盒身份和标签/打印历史。P16 只形成业务计划和可追溯事实，不形成物理石蜡块。

## 2. 需求、验收和场景映射

| 正式输入 | P16处理 | 状态 |
|---|---|---|
| P09-REQ-0021 组织取材记录 | 取材批次、身份核对、外观/数量、大体描述、不可变记录 | P16实现 |
| P09-REQ-0022 蜡块业务记录和编号 | 计划蜡块、来源关系、DEV/test并发安全编号 | P16实现 |
| P09-REQ-0023及其后的处理/包埋/物理形成 | 只保留交接边界 | 后续阶段 |

P09-REQ-0021/0022 各有正向和负向验收条件，共 4 个直接验收条件。`SCN-PIS-020` 至 `SCN-PIS-024` 五个取材与标签场景纳入测试：单标本取材、多蜡块来源、多标本分离、大体描述、标签提交与重打。

## 4. 状态与禁止项

批次状态：`PLANNED` → `ASSIGNED`/`TAKEN_OVER` → `IN_PROGRESS` ↔ `PAUSED` → `COMPLETED` → `HANDED_OFF`；异常路径为 `CANCELLED` 或 `TERMINATED`。计划蜡块使用 `P08-SM-004-ST-01`（待取材）和 `P08-SM-004-ST-02`（取材已记录），不设置物理形成时间。

禁止 `setStatus`、`updateStatus`、PATCH状态、前端最终编号、`SELECT MAX + 1`、直接覆盖已完成取材事实、无来源取样、无理由重打、浏览器打印成功冒充物理打印成功。

## 5. 交付门禁

P16 只有在后端、前端、迁移、Docker、P15回归、并发、静态检查和关闭审查全部通过后才允许提交和推送。任何一项失败均保持 P16 进行中。
