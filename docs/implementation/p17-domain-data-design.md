# P17 领域与数据设计

P17 不复制蜡块主数据。P16 已建立的 `pis.tissue_block` 保持稳定业务身份和计划编号；P17 只在包埋完成时追加实际形成事实，并更新同一蜡块的物理形成时间和生命周期。这保证“计划蜡块”与“实际形成事实”可区分，且不生成重复主记录。

## 新增表

V5 新增 15 张表：处理任务、任务责任、处理程序、程序版本、程序步骤、处理批次、批次成员、处理运行、运行步骤、原始结果、有效结果、处理异常、成员影响、恢复记录、重处理记录。V6 新增 5 张表：包埋任务、包埋责任、包埋事实、实际蜡块形成、实际蜡块替代关系，共 20 张 P17 表。

全部核心表使用不可变 UUID 主键和业务号分离；必要的组织范围、唯一约束、外键、检查约束、索引和乐观并发版本均在迁移中声明。医疗业务记录不物理删除，作废、替代和重处理均追加事实。

## 关键约束

- 同一组织范围内任务号、批次号、包埋任务号唯一。
- 同一批次与计划蜡块只能有一个成员；同一运行与成员只能有一个有效结果。
- 外部消息 ID 全局唯一；同一幂等键的负载摘要变化返回 `P12-ERR-003`。
- 实际形成按 `(tissue_block_id, formation_version_no)` 唯一；替代关系保留原形成事实。
- `physical_formed_at` 为空且蜡块处于 `P08-SM-004-ST-02` 才允许首次形成；形成后为 `P08-SM-004-ST-03`。
- 所有跨范围读取通过组织范围条件；责任、状态历史、审计和 outbox 在同一事务边界内写入。
