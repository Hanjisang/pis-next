# P05 核心领域关系与来源链

文档状态：已确认
阶段：P05
任务：P05-001-FINAL
最后更新：2026-08-06

## 1. 文件定位

本文件定义 P05 的领域对象关系、来源链、责任链和事实分层。它不是数据库 ER 图、外键设计、接口契约、页面流程或代码类图。关系中的“引用”表示稳定业务身份之间的领域关联，不表示某种技术存储方式。

关系判断遵守：

1. 患者安全、来源完整性和责任可追溯优先；
2. 下级对象保留独立身份、生命周期和历史事实；
3. 物理过程只有在形成新材料、责任转移、诊断/报告影响或异常质量事实时才形成明确业务记录；
4. 计划、标签、实物、技术结果、数字版本、报告版本和呈现文件不得混同；
5. 关系纠错保留原关系、新关系、原因、人员、时间和影响范围。

## 2. 患者、就诊、申请和病例

```text
患者引用
└─ 就诊引用
   └─ 病理申请
      └─ 形成或关联病理病例
```

上述是候选业务关系的正式表达，不规定申请与病例的固定基数，也不把关系转换为数据库约束。

### 2.1 关系结论

| 对象 | 关系结论 |
|---|---|
| 患者引用（OBJ-010） | 外部医疗上下文引用。PIS 保存稳定本地引用身份、外部患者标识和来源系统，不维护医院完整患者主数据。 |
| 就诊引用（OBJ-011） | 外部医疗上下文引用。一个患者可以关联多个就诊引用；就诊号不等于病理号。 |
| 患者与就诊快照（OBJ-012） | 绑定病例建立、接收、签发或其他关键事实的版本/快照。快照不是患者或就诊引用的替代品。 |
| 外部申请标识（OBJ-013） | 入站外部事实记录。外部消息、外部标识和本地病理申请分别保留。 |
| 病理申请（OBJ-001） | PIS 管理的服务请求事实，可以先于病例存在。申请取消不删除病例或下游事实。 |
| 病理病例（OBJ-002） | PIS 本地组织病理业务对象。内部身份与病理号分离，病例展示汇总不覆盖下级事实。 |

患者、就诊主数据更新不得自动覆盖已绑定申请、病例或报告版本中的历史上下文。错患者纠错必须保留原关系、新关系、原因、责任人、复核和受影响下游对象。

## 3. 物料来源主链

```text
病理病例
    ↓
标本
    ↓ 取材事实
蜡块业务记录
    ↓ 制片事实
实际玻片
    ├─→ 直接作为诊断依据
    └─→ 扫描任务 → 数字切片版本 → 文件完整性/质量校验 → 作为诊断依据
```

诊断记录还可以引用：

- 一个或多个标本；
- 一个或多个蜡块业务记录；
- 一个或多个实际玻片；
- 一个或多个具体数字切片版本；
- 特殊染色、免疫组化、分子检测及其他已确认技术结果；
- 必要的关键临床资料。

数字切片是可选分支，不要求所有实际玻片必须扫描，也不要求所有诊断必须经过数字切片。只有数字文件而没有实体玻片时，使用外部数字材料（OBJ-020），不得虚构本地实际玻片。

### 3.1 标本和容器

一个病例可以有多个标本；每个标本具有独立身份、来源、接收、数量差异、异常、交接和后续处理事实。部分标本异常只影响相关标本及其下游，病例级汇总不得替代标本事实。已确认标本可以独立进入后续处理，不必等待同病例其他标本。

标本容器（OBJ-038）默认只表达物理承载信息。启用医院扩展时，才增加容器稳定身份、扫码、位置、物流或交接关系；容器不得替代标本身份。不启用扩展时，标本关系仍完整成立。

### 3.2 蜡块业务记录

```text
标本
  → 取材事实
  → 蜡块业务记录
  → 组织处理轻量记录
  → 包埋完成事实
  → 物理石蜡块形成
```

蜡块业务记录（OBJ-004）在取材形成明确蜡块计划和编号时建立，物理石蜡块在包埋完成后形成，通常继续沿用同一蜡块业务身份和蜡块号。蜡块业务记录不等于组织盒、组织处理批次或单纯包埋完成状态。

- 同一物理蜡块继续重脱水、重包埋或其他返工：沿用身份，新增操作事实；
- 剩余组织补块或拆分形成新的可独立切片蜡块：建立新身份和新蜡块号，并保留来源标本、原蜡块和取材关系；
- 组织盒扩展（OBJ-039）可以承载蜡块业务记录，但不改变蜡块身份；
- 蜡块作废保留身份、编号、原因、责任和影响，不得继续形成有效下游材料。

### 3.3 计划玻片、标签和实际玻片

```text
技术医嘱或制片计划
        → 计划玻片
        → 标签创建/打印
        → 实际玻片
```

计划玻片（OBJ-017）表达用途或单片计划；标签是标识物；实际玻片（OBJ-005）是已经形成并进入技术、诊断、扫描、外送或归档范围的物理业务对象。

- 技术医嘱只给出数量和用途时，不强制立即创建逐片计划身份；
- 标签打印不表示实际玻片已经形成；
- 新制作物理玻片建立新身份；
- 同一实际玻片去色、重染或继续处理沿用原身份并新增操作事实；
- 重新制作形成新物理玻片时建立新身份；
- 外院实体玻片建立本地引用或稳定本地身份，并保留外部来源标识。

### 3.4 数字切片

实际玻片（OBJ-005）是数字切片版本（OBJ-019）的物料来源；数字切片版本是扫描结果的版本事实，不属于蜡块。

- 一个实际玻片可以有多个数字切片版本；
- 重扫形成新数字切片版本；
- 同一文件重复传输只形成投递/幂等事实，不形成新扫描版本；
- 设备报告扫描成功不自动等于文件可诊断，须经过完整性和质量确认；
- 诊断或报告引用固定到实际使用的数字切片版本；
- 外部数字材料保留来源机构、外部标识、身份依据、文件质量和使用限制。

## 4. 技术医嘱和技术执行

```text
技术医嘱
   → 计划目标
   → 实际执行目标
   → 技术执行记录
   → 实际产物或操作结果
```

技术医嘱（OBJ-015）是需要提出、授权和追踪的技术请求，不等于临床医嘱、收费项目或技术任务。标准化常规任务可以由规则形成；需要医学判断、高风险、高成本或明显消耗材料的项目由授权角色确认。医嘱执行前必须落到具体目标对象，目标可以是标本、蜡块或实际玻片。

技术执行记录（OBJ-016）记录目标、实际人员或设备服务身份、时间、结果、异常、质量确认和返工。计划目标和实际目标分离；无物理产物的操作不得虚构产物；设备成功不自动等于业务完成；失败和返工不覆盖原执行事实。

组织处理批次（OBJ-024）是可选的轻量工作组织和责任记录，不替代单个蜡块业务记录；批次内部分成功、部分失败时，逐对象结果和异常仍独立保留。

## 5. 术中冰冻

```text
冰冻业务
   → 冰冻轮次
      → 轮次材料记录
      → 冰冻意见/反馈
   └─→ 冰剩材料
          → 常规蜡块业务记录
          → 实际玻片
```

### 5.1 冰冻业务和轮次

冰冻业务（OBJ-021）归属于一个病例，可以关联一个或多个标本，包含一个或多个冰冻轮次（OBJ-022）。同一冰冻业务不得跨多个病例形成。

每次独立送检形成一轮；前轮诊断意见形成前追加材料可以进入原轮，前轮意见形成后再次送检建立新轮次。一轮可以有多个标本，但必须逐标本追溯。轮次不替代标本身份。

冰冻材料或轮次材料记录（OBJ-023）记录轮次内实际接收、追加、来源冲突、消耗和关闭结果；可沿用原标本身份或使用轮次内临时标识，临时标识转正式身份时保留关系。

### 5.2 冰冻报告和冰剩

口头初步意见、正式冰冻报告和最终石蜡报告分开表达。形成并反馈独立意见的轮次形成独立报告事实或报告版本事件；冰冻报告不能被最终报告无痕覆盖。冰冻与最终诊断重大差异保留原因、通知和责任结果，并遵守报告更正、撤回和重新签发规则。

冰剩默认沿用原标本来源，不重复建立无价值的来源标本。冰剩转常规时，可形成一个或多个新的常规蜡块业务记录，使用常规蜡块编号规则并保留冰冻业务、轮次和原标本关系。材料不足、已消耗或不转常规必须形成明确关闭结果。

## 6. 诊断、报告和呈现

```text
诊断任务
   → 分配/接管/转交/退回/初诊/复诊/审核责任
   → 诊断记录
      → 固定引用材料、数字版本、技术结果和临床资料
      → 报告版本
         → 报告生命周期
            → PDF呈现文件
```

诊断任务（OBJ-006）表达工作分配和责任承担，不表达医学结论。诊断记录（OBJ-007）表达医学意见、依据、实际人员和时间。任务变化不得覆盖已经形成的诊断记录；会诊、代理和诊断分歧独立留痕；新依据影响结论时形成重新确认事实。

报告生命周期（OBJ-008）连接同一报告业务的正式签发、补充、更正、撤回和重新签发历史。报告版本（OBJ-009）是每次正式医学事件形成的不可覆盖事实，绑定签发时患者、就诊、病例及必要标本快照，固定诊断依据和签发责任。报告生命周期不得替代报告版本，当前有效版本只能通过受控报告事件变化。

PDF呈现文件（OBJ-042）绑定具体报告版本和模板版本。医学内容一致时可以重新生成 PDF，但必须保留文件历史和一致性校验；医学内容或签发责任变化必须形成新报告版本。PDF 生成、回传或存储失败不回滚本地报告版本事实。

## 7. 外部事实和接口关系

```text
本地业务事实
      → 出站业务事件
         → 接口投递记录
            → 外部技术应答
               → 外部业务状态
                  → 对账结果
```

五层事实分别表达：

1. 本地业务事实是 PIS 已形成的申请、报告、版本或其他业务结果；
2. 出站业务事件（OBJ-032）表达应向外部系统传达的本地事实；
3. 接口投递记录（OBJ-033）表达一次发送、应答、失败、重试或补偿；
4. 外部技术应答和外部业务状态表达外部系统已接收、处理或拒绝的事实；
5. 对账差异记录（OBJ-034）表达本地与外部事实之间的差异、判断、处置和关闭证据。

只有本地事实成功形成后才能产生出站业务事件。重试或重放沿用原业务事件身份，不生成新的本地医学或物料事实。旧版本不得覆盖新版本；错患者、错报告、错版本和撤回失败进入人工处理与质量评估。

## 8. 责任、授权、审计、档案和恢复

### 8.1 责任关系

责任关系由操作责任记录（OBJ-025）、交接记录（OBJ-026）、技术执行记录（OBJ-016）、受控纠错记录（OBJ-029）、授权与代理记录（OBJ-030）和审计事件（OBJ-031）分别表达。每项责任至少保留责任对象、实际人员或服务身份、责任角色、操作类型、发生时间、结果、必要异常、代理关系和责任转移关系。

申请建立、标本接收和交接、取材、技术医嘱、技术执行、质控、诊断、复诊、审核、签发、代理授权、纠错、质量处理、服务身份执行和审计责任分别留痕。

实际人员与责任角色分离；人工身份与服务身份分离；系统管理员不自动获得业务责任；代理操作记录实际操作人；同一人员承担多个角色时分别确认；责任转移不得覆盖原责任；服务自动执行不得伪装成人工操作；交接未签收不得标记为完成。

### 8.2 记录分层

以下对象不得合并成万能日志：

- 技术日志：设备或服务运行证据；
- 业务操作责任记录：业务动作和责任事实；
- 交接记录：材料或责任转移事实；
- 异常记录：局部异常及处理结果；
- 质量事件：需要质量评估的高风险事实；
- 受控纠错记录：原事实、新事实、原因、复核和影响；
- 授权与代理记录：授权范围、期限和实际执行人；
- 审计事件：关键业务动作和证据保护。

技术日志不等于业务审计、质量事件或受控纠错事实。

### 8.3 权限、档案和恢复

授权关系包括组织、角色、功能授权、数据范围、临时授权、代理关系、紧急授权和有效期；P05 不规定具体权限点。系统管理与业务纠错分离，高风险操作使用可识别个人身份和强认证，权限撤销不删除历史责任。

档案销毁记录（OBJ-035）只记录通过保留期限、审批和冻结检查后的受控销毁；核心病例、来源、正式报告、签发责任和审计事实不得普通删除。恢复任务（OBJ-036）和恢复校验结果（OBJ-037）与原业务对象分离；恢复后必须核对身份、来源、版本、文件、权限和审计，已销毁或被冻结对象不得因旧备份恢复而重新成为有效对象。

## 9. 领域关系与后续阶段

P05 正式确定关系语义和历史保护，不确定数据库存储、接口字段、完整状态枚举和页面操作。详细业务流程交给 P06，异常场景交给 P07，对象状态机交给 P08，需求基线交给 P09，架构和事务技术策略交给 P10，数据库交给 P11，接口契约交给 P12，权限实施交给 P14，页面与工作站交给 P24，测试交给 P25，部署与灾备交给 P27。
