## 1. 文件定位

本文件当前为候选识别基线。“候选对象”不等于最终实体、聚合根、数据库表或代码类。最终分类和聚合边界将在后续 P05 工作包中逐步确认。

### 8.1 医疗上下文

#### P05-OBJ-010 患者引用

- **规范术语/对象名称/分类**：患者引用；医疗上下文引用。
- **是否由 PIS 自主拥有**：外部上下文引用。
- **业务定义**：引用医院患者权威身份，不是 PIS 患者主档案、统一患者主索引或所有患者资料的权威来源。PIS 保存稳定本地引用身份、外部患者标识和来源系统，用于连接申请、病例和报告历史。
- **产生时点/稳定内部身份**：首次接收或建立可追溯患者上下文时产生；需要稳定本地引用身份，是。
- **业务编号/外部标识**：本地引用身份不等于业务编号；外部患者标识与来源系统必须分开保存。
- **直接来源/主要下游**：HIS、EMR、主索引或其他已确认来源；申请、病例、患者与就诊快照、报告版本。
- **生命周期责任主体**：外部患者主数据责任方负责权威身份；PIS 业务责任人负责引用绑定、冲突处置和纠错。
- **允许变化的当前信息/不可覆盖历史事实**：当前显示资料可按权威来源受控更新；原外部标识、来源、关联关系、合并/拆分、纠错原因、责任人和影响范围不可覆盖。
- **相邻对象边界**：不等于患者主数据、不等于就诊引用、不等于快照；患者合并或拆分不得改写历史报告上下文。
- **候选不变量**：外部标识不得替代本地身份；外部变化不得覆盖历史快照；错患者纠错保留原关系、新关系及影响范围。
- **医院配置边界**：权威来源、字段优先级、冲突分级、展示字段和纠错复核级别可配置；不在 P05 重定义患者主索引。
