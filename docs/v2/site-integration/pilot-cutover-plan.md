# S07 Pilot & Cutover Preparation

文档状态：PLAN READY

真实医院 Pilot/Cutover：NOT STARTED

## 1. 角色与责任

以下责任人必须在医院项目启动后实名确认：业务负责人、病理科负责人、信息科负责人、接口负责人、数据库负责人、安全负责人、迁移负责人、设备负责人、现场支持和回滚批准人。当前均为：待业务确认。

S07-CUT-001：任何单个技术人员不得同时批准迁移、切换和回滚；医疗数据差异必须由业务与数据责任人共同决策。

## 2. Pilot 前置 Gate

1. Hospital Profile 已由医院确认并冻结版本；
2. 真实身份、组织、权限和离职停用完成验收；
3. HIS/LIS/EMR/报告交付接口完成正常、重复、乱序、超时、重试、死信和对账；
4. 打印机、扫描仪和人工降级完成现场测试；
5. 两轮全量迁移演练和一次增量演练无 P0/P1 未决异常；
6. 性能、备份恢复、安全和监控通过生产门禁；
7. 培训、SOP、值班和升级通道就绪；
8. Cutover 与 Rollback 演练完成并有签字证据。

任一项未完成时 Pilot 不得开始。

## 3. Pilot 计划

建议顺序为：隔离测试环境 → 单院区/受控 BusinessType → 受控用户组 → 扩大时段和业务量 → 全量评审。实际范围、日期和病例类型为待业务确认。

Pilot 每日检查：

- 登记、材料、诊断、签发和 PDF 数量；
- 责任人、病理号、材料来源和报告链抽样；
- 接口失败、死信、重放和对账差异；
- 标签补打、扫描回调和设备降级；
- 性能、错误率、数据库、存储和备份；
- 用户问题、严重度、处置人和关闭证据。

S07-CUT-002：Pilot 数据必须明确是测试、影子还是正式医疗事实；禁止在两个系统同时写正式业务后再人工猜测合并。

## 4. 上线前准备

T-14 至 T-1 的具体时间点由医院确认，至少完成：

1. 发布制品、配置版本、Flyway checksum 和回滚制品冻结；
2. 生产数据库全备和恢复验证；
3. Legacy 全量迁移、异常清单和关系对账；
4. 增量同步演练及预计停机窗口；
5. 外部接口切换、DNS/网关、打印机和扫描仪变更单；
6. 用户账号、权限、培训和现场排班；
7. Go/No-Go 会议和签字。

## 5. Cutover Runbook

执行窗口内按顺序进行：

1. 宣布窗口开始，记录 UTC/本地时间和责任人；
2. 停止 Legacy 新写入，验证所有写入口已关闭；
3. 捕获最终增量快照和摘要；
4. 执行增量迁移，处理或明确阻断所有 P0/P1；
5. 核对 Case、Specimen、Block、Slide、Diagnosis、Report 数量和关系；
6. 切换接口目标和 V2 正式入口，禁止双写；
7. 以真实认证角色完成受控烟测：登记→材料→诊断→签发→PDF；
8. 验证报告交付、标签打印、查询、归档和监控；
9. 业务、数据、接口和技术负责人共同 Go；
10. 将 Legacy 保持只读历史查询/迁移源，进入加强监控期。

S07-CUT-003：如果最终增量或关系对账不通过，不能通过忽略异常进入 V2。

## 6. Rollback Gate

具体阈值须在医院项目中量化。以下事件至少触发回滚评估：

- 患者/病例/材料错误绑定或不可追溯；
- 已签发报告内容、责任人、版本链或 PDF 错误；
- 无法可靠登记、制片、诊断或签发；
- 权限越权、审计缺失或敏感数据暴露；
- 接口积压超出批准阈值且无安全人工降级；
- 数据库损坏、恢复点丢失或关键性能持续不达标。

回滚步骤：

1. 回滚批准人宣布停止 V2 新写入；
2. 保全 V2 数据库、日志、消息和审计快照，禁止删除；
3. 确认 V2 窗口内已产生的医疗事实清单；
4. 恢复 Legacy 写入口前，由业务负责人决定这些事实的受控补录/同步方式；
5. 恢复接口目标并执行双向数量/关系对账；
6. 验证 Legacy 核心烟测后开放；
7. 建立事故、数据差异和人工复核清单。

S07-CUT-004：回滚不是数据库简单还原。V2 窗口内新增的医疗事实必须保留和逐项处置，禁止静默丢失或覆盖。

## 7. 上线后观察

上线后观察周期、值班频率和退出标准为待业务确认。退出加强监控至少要求：无 P0/P1 未决、每日对账连续通过、备份可恢复、接口和设备稳定、业务抽样通过、用户问题已分级并有负责人。

当前计划不批准实际 Pilot、Cutover 或 Legacy 正式数据迁移。
