# PIS-Next V2 P09 切换计划

文档状态：计划
文档版本：V2-0.1

## 1. 切换前提

P09 不开始于当前文档阶段。必须先完成 P04 数据模型、P06 API、P08 测试、迁移映射批准、权限审查、备份恢复演练和业务用户验收。

## 2. 阶段

1. **隔离开发**：V2 代码、数据库和测试与旧资产隔离；
2. **合成数据验证**：使用虚构/脱敏数据验证核心闭环和异常场景；
3. **迁移演练**：在独立迁移工作区执行可重跑迁移，输出 MigrationWarning/ManualReview；
4. **并行对账**：按病例、材料、报告快照、审计和接口记录比较，不以数量相等代替一致性；
5. **受控试点**：限定院区、BusinessType、角色和可回滚范围；
6. **正式切换**：满足准入门禁后切换入口，保留旧系统只读和回退窗口；
7. **稳定观察与清理**：确认 V2 业务稳定后，按批准记录清理旧 Planned/Actual、旧 Task 和兼容代码。

## 3. 切换门禁

- 核心身份、来源链、报告不可变、审计和权限检查通过；
- 迁移前后每类对象数量、唯一性、关系和文件哈希已对账；
- 所有 MigrationWarning/ManualReview 有责任人和处理结论；
- 备份恢复演练通过，恢复后不会使撤回、销毁或失效对象重新有效；
- 外部接口失败、重试、死信、人工重放和回传超时有补偿；
- 业务用户完成 Diagnosis Workspace、材料追溯和报告生命周期验收；
- 未验证的能力和剩余风险已公开记录，不以“完成率”替代上线准入。

## 4. 禁止事项

不得强杀正在使用的旧系统或直接覆盖生产数据库；不得在迁移无法可靠映射时静默猜测；不得在未完成业务验收、备份恢复和回退演练前宣布 V2 上线。
