## 1. 文档目的

本文确立 PIS Next 技术流程的轻量化原则，确保系统同时满足实验室操作效率、物料来源追溯和操作责任追踪要求。

本文只记录流程原则、技术对象重新评估和后续修订范围，不创建领域实体、值对象、聚合、数据库、API、页面或完整状态机。

## 2. 总体原则

正式采用：

```text
真实物理流程 ≠ 强制系统操作流程
```

系统只对以下事项要求明确记录：

1. 产生新的可追溯物料；
2. 责任人或责任部门发生变化；
3. 关键业务阶段完成；
4. 发生异常或质量风险；
5. 形成诊断、报告等医疗业务结果。

不满足以上条件的物理动作，不得默认设计为强制人工系统节点。

后续新增人工节点必须说明其是否产生新物料、发生责任转移、影响患者安全或必须记录异常；上述条件均不满足时，不得加入强制流程。

## 3. 两条核心追溯链

### 3.1 物料来源链

```text
病理病例
→ 标本
→ 蜡块业务记录
→ 玻片
→ 诊断报告
```

系统必须能够回答玻片来自哪个蜡块、蜡块来自哪个标本、标本属于哪个病例和患者，以及报告使用了哪些玻片和标本。

### 3.2 操作责任链

每项需要记录的操作至少保留：

```text
操作对象
＋ 操作类型
＋ 操作人员
＋ 操作时间
＋ 操作结果
＋ 必要异常
```

至少覆盖取材、脱水、包埋、制片、玻片标签打印、诊断任务分配、诊断、审核和报告签发。设备自动执行时，可以记录确认人员、设备、批次和自动回传时间。

## 4. 实际物理流程与 PIS 核心流程

实际物理流程仍然是：

```text
取材
→ 脱水/组织处理
→ 包埋
→ 切片
→ 染色
→ 封片
```

PIS 核心流程调整为：

```text
标本接收
→ 取材并创建蜡块业务记录
→ 脱水完成记录
→ 包埋完成记录
→ 制片并创建玻片
→ 技术完成
→ 分配诊断
→ 诊断和报告
```

不得要求每个物理过程都具有独立页面、复杂状态机或逐步人工确认。

## 5. 核心技术流程原则

### 5.1 蜡块业务记录

蜡块业务记录是技术流程中的核心追溯记录。取材时建立蜡块业务记录，分配通常采用“病理号-蜡块序号”的蜡块号，打印组织盒标签，并记录来源标本、取材人员和取材时间。

取材阶段物理石蜡块尚未形成，但蜡块业务记录已经建立。该记录贯穿取材、组织盒承载、脱水、包埋和切片。

默认不要求建立独立组织盒核心对象、独立物理蜡块版本对象或独立包埋结果对象；需要逐盒物流或自动化设备追踪的医院，可以启用组织盒扩展能力。

### 5.2 取材

取材是系统重点环节，应在一个页面或连续工作界面中支持取材描述、大体描述、来源标本、蜡块创建和排序、蜡块号、组织盒标签打印、取材人员、取材时间、特殊处理说明以及受控纠错。

### 5.3 脱水/组织处理

脱水采用轻量完成记录，至少记录完成时间、操作或确认人员、完成结果和必要异常；处理批次和设备为可选信息。允许批量选择蜡块并一次确认，设备可回传时优先使用设备数据，不要求手工记录试剂、温度、时间段或设备内部程序。

### 5.4 包埋

包埋采用轻量完成记录，至少记录完成时间、操作人员、完成结果、是否重包埋和异常说明，允许批量确认。

默认不建立复杂包埋任务生命周期、独立包埋活动领域对象、物理蜡块版本、包埋方向审批或普通包埋双人复核。重包埋在原蜡块下增加操作记录，保留原包埋信息，默认不改变蜡块号；只有拆分形成多个可独立切片的蜡块时，才新增蜡块记录。

### 5.5 制片与玻片

制片是系统重点环节，应支持来源蜡块、制片人员和时间、实际玻片数量、玻片记录、玻片编号、玻片标签打印、补切、重切、深切、白片、特殊染色用片、玻片作废、标签重打和制片异常。

每张需要独立诊断、扫描、染色或追溯的玻片必须具有独立身份。

### 5.6 玻片标签预打印

允许在脱水阶段、脱水完成后、包埋完成后、正式切片前、技术医嘱下达后或批量制片准备时打印玻片标签。

必须区分：

```text
计划玻片 ≠ 已打印玻片标签 ≠ 已制作物理玻片 ≠ 已完成技术处理
```

预打印记录至少保留来源蜡块、计划玻片类型、打印人员、打印时间、是否实际使用、是否作废和是否重打。标签已打印不代表物理玻片已经形成。

### 5.7 染色、封片与技术完成

常规染色和封片不作为第一版强制人工系统节点。可采用不单独记录、设备自动回传、简单完成时间、异常记录或技术完成统一确认等方式。

特殊染色、免疫组化、分子检测、设备对接、染色批次、设备故障和质量事件可以作为扩展能力。

玻片满足诊断条件后完成技术流程，系统记录技术完成人员、完成时间、可诊断玻片数量及未完成或异常玻片。

### 5.8 诊断任务分配

诊断任务分配是核心责任转移，必须记录分配人员、分配时间、被分配诊断医生、改派人员、改派时间、改派原因和诊断医生接收情况，不得只通过病例状态字段表达责任转移。

## 6. 系统操作最小化

所有正常操作应支持当前人员自动带出、时间自动记录、批量完成、扫码触发、设备回传、默认值和医院配置；正常操作尽量一键完成，只有异常时要求额外填写，不重复录入上游已经存在的信息。

## 7. 受控纠错与历史

本原则继续遵守已确认的业务信息灵活修改与受控纠错原则：

- 允许授权业务人员在合理阶段纠正信息；
- 不得无痕覆盖操作记录、来源关系或异常事实；
- 修改已被下游使用的信息时必须评估影响；
- 已签发报告必须通过报告版本生命周期处理；
- 系统管理员权限不得自动获得业务纠错权限。

## 8. 首批技术对象重新评估

P05 的候选核心对象暂收敛为：

```text
病理申请、病理病例、标本、蜡块、玻片、诊断任务、报告、报告版本
```

通用记录包括业务操作记录、任务分配记录、异常记录和审计记录。

标本容器、组织盒、脱水活动、包埋活动、染色活动、封片活动、物理位置轨迹和物理蜡块版本默认不作为强制核心对象；医院有明确需求时再评估扩展能力。

BD-P04-020、BD-P04-025、BD-P04-026、BD-P04-027 进入技术流程模型修订/暂停确认状态，不在本任务中形成新的业务确认结论。
