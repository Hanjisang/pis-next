# P12 幂等、并发、版本、错误和兼容契约

文档状态：P12已基线化
幂等写操作：54项（42个内部命令、12个正式医院/外部接口）；使用外部消息幂等的接口：12项；使用预期版本控制的操作：27项；稳定错误代码：82项，其中患者安全关键15项。

## 1. 幂等操作登记

所有42个内部命令均有幂等结论。创建类命令使用业务身份、来源身份或操作意图；变更类命令增加预期版本；外部入站/出站使用目标、来源消息、事件/对象版本和载荷摘要。以下分组覆盖每一个正式操作，组内每个API编号均适用同一规则。

| 操作范围 | 覆盖数量 | 幂等键 | 同载荷重复 | 不同载荷/并发 | 失败和审计 |
|---|---:|---|---|---|---|
| P12-API-001–006 申请/病例 | 6 | source_system + source_message或application/case identity + intent | 返回首次接收/建立/取消事实 | 摘要不一致为ERR-003；版本冲突为ERR-010 | 保存原文、处理结果、责任和关联 |
| P12-API-007–012 纠错/标本/交接 | 6 | correction/handoff/receipt identity + payload digest | 返回既有事实，不重复接收或交接 | 不同来源或版本冲突隔离 | 记录原值、新值、责任和审计 |
| P12-API-013–018 组织技术/数字材料 | 6 | source material + attempt/target identity + version | 引用原尝试或实际材料 | 物理身份冲突不复用；新尝试追加 | 形成技术/文件异常和质量证据 |
| P12-API-019–026 冰冻/细胞 | 8 | case/round/preparation/task + action intent + version | 返回既有轮次、反馈、评价或诊断事实 | 迟到进入复核；不同摘要冲突 | 责任、评价、复核和患者安全审计 |
| P12-API-027–033 分子/外送 | 7 | task/material/run/external organization + external version + digest | 返回原任务、原运行或原外部结果 | 质控、材料和外部版本冲突隔离 | 原始载荷、设备/机构身份和核验审计 |
| P12-API-034–042 诊断/报告/治理 | 9 | responsibility/report/governance identity + event kind + version | 返回原诊断、报告事件或治理事实 | 已签发/销毁/恢复冲突拒绝或人工复核 | 强认证、复核、影响范围和审计 |
| P12-HIF-001 | 1 | source_system + source_message + external_application + source_version + digest | 返回首次接收和处理状态 | 不同摘要ERR-003；乱序进入待处理 | 保存原始消息、接收和对账 |
| P12-HIF-002 | 1 | source_system + source_message + external_order_or_charge + version + digest | 返回关联事实 | 关联冲突进入对账 | 保存外部事实，不改医学事实 |
| P12-HIF-003 | 1 | source_system + source_message + external_task/report_version + digest | 返回原外部结果接收事实 | 版本冲突隔离 | 保存来源核验和本地核验 |
| P12-HIF-004 | 1 | target + event + subject + subject_version + digest | 返回原投递状态 | 目标版本冲突对账 | 技术/业务应答分开 |
| P12-HIF-005 | 1 | target + event + association_version + digest | 返回原关联投递 | 迟到或业务拒绝进入差异 | 本地事实不回滚 |
| P12-HIF-006 | 1 | target + report_event + report_version + file_version + digest | 返回原报告回传 | 版本不一致拒绝或对账 | 具体报告/文件版本审计 |
| P12-HIF-007 | 1 | target + governance_event + original_event + new_event | 返回原纠错/撤回通知 | 业务不支持或顺序冲突对账 | 记录人工补偿和确认 |
| P12-HIF-008–011 | 4 | adapter + task/run/slide/file identity + attempt/version + digest | 返回原设备/文件回执 | 原始载荷冲突隔离 | 设备身份、质量、文件完整性审计 |
| P12-HIF-012 | 1 | external_org + external_task + external_report_version + digest | 返回原外送/结果事实 | 机构或版本冲突人工核验 | 交接、核验、剩余材料和对账 |

上述表合计：42个内部命令 + 12个正式外部接口 = 54个幂等写操作；所有12个HIF均使用外部消息或目标消息幂等。

## 2. 预期版本控制

以下27项操作必须带`P12-SCH-019`预期业务版本：`P12-API-003`、`004`、`005`、`006`、`007`、`009`、`010`、`011`、`013`、`014`、`015`、`017`、`018`、`020`、`024`、`025`、`026`、`028`、`030`、`031`、`032`、`034`、`035`、`036`、`038`、`039`、`040`、`041`。创建新身份的命令可以没有预期版本，但必须使用创建幂等键；文件和外部接口使用目标/对象版本而不是数据库字段名。

版本冲突统一返回`P12-ERR-010`或按患者安全等级返回更具体错误；响应必须带当前版本、请求版本、重新读取要求和是否允许安全重试。禁止静默覆盖，重试前必须重新读取授权、状态、材料来源、报告版本或治理范围。

## 3. 契约版本和兼容规则

API契约版本、公共Schema版本、事件版本、医院适配器版本、业务对象版本、报告版本和文件版本独立编号。兼容规则如下：

| 兼容编号 | 变化 | 处理 |
|---|---|---|
| P12-COMP-001 | 新增可选请求或响应字段 | 旧消费者忽略并保留；不改变既有语义 |
| P12-COMP-002 | 新增枚举/状态映射值 | 适配器将未知值隔离或保留，不默认为已有值 |
| P12-COMP-003 | 字段弃用 | 先保留旧字段和语义，登记迁移窗口；不得静默删除 |
| P12-COMP-004 | 字段语义或时间语义改变 | 新Schema/API版本；旧版本继续按原语义处理 |
| P12-COMP-005 | 必填字段增加 | 新版本并行；旧消费者不被突然阻断 |
| P12-COMP-006 | 结构拆分或聚合改变 | 新Schema和映射；不把数据库列迁移当作契约兼容 |
| P12-COMP-007 | 错误代码新增 | 旧消费者按错误类别安全处理；旧代码不改义 |
| P12-COMP-008 | 事件Envelope变化 | 新事件版本，明确生产者、消费者、重放和停止支持条件 |
| P12-COMP-009 | 医院接口双版本 | 通过适配器并行，不污染核心Schema |
| P12-COMP-010 | 停止支持 | 需要正式通知、消费者确认、审计和回退方案；参数不写死 |

## 5. 错误与补偿

契约错误、认证/授权错误和对象/版本错误优先在命令入口拒绝；外部依赖和文件错误可进入重试/受阻任务；业务确认和对账差异必须形成独立差异记录；患者安全错误阻断相关后续动作但不机械阻断无关病例、标本或模态路径。
