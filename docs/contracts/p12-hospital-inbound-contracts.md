# P12 医院入站接口契约

文档状态：P12已基线化
正式入站接口：P12-HIF-001至003，共3项。外部协议、字段名称、代码值、地址和认证方式均待具体接入项目配置；本文件只定义规范化语义和适配边界。

## 1. 入站共性处理

入站顺序为：可信认证上下文形成 → 接收原始消息 → 校验来源和契约版本 → 提取来源消息身份 → 保存载荷摘要和原文引用 → 规范化映射 → 调用本地业务命令 → 返回技术接收结果 → 形成业务事实或业务待处理结果 → 记录事件、审计和对账入口。技术接收成功不等于申请建立、病例建立或外部结果核验成功。

每个接口必须提供`P12-SCH-001`请求上下文和`P12-SCH-020`外部消息；原始消息不可被新消息覆盖。重复同载荷返回第一次处理结果；相同幂等身份但摘要不同返回幂等冲突；处理中重复返回处理中引用；乱序或取消先到进入受控待处理，不按最后到达消息静默覆盖。

## 2. P12-HIF-001：医院患者就诊和病理申请入站

| 契约项 | 规定 |
|---|---|
| 来源系统 | HIS、EMR或临床申请适配器；具体系统名称待接入配置 |
| 业务目的 | 接收患者/就诊外部上下文和病理申请原始事实，建立申请接收或待人工归并入口 |
| 传输风格 | 未确认；可由消息、受控调用或人工补录适配，核心契约不绑定协议 |
| 触发方式 | 外部申请、新版本申请、申请取消或受控补传 |
| 请求Schema | SCH-001、003、004、020 |
| 必填 | request_identity、source_system_code、source_message_identity、source_message_version、payload_digest、request_received_at、pathology_modality_code、application_identity或外部申请身份 |
| 条件必填 | 患者或就诊引用至少一项；申请取消必须有原申请身份、取消原因和外部业务时间；更新必须有外部版本；手工补录必须有人工主体和原因 |
| 患者处理 | 只保留外部患者引用和业务时点快照；不创建或修改患者主数据 |
| 就诊处理 | 只保留外部就诊引用和快照；缺失或冲突进入身份核对，不自动绑定错误病例 |
| 病理类型 | 使用已确认病理类型语义；医院代码通过适配器映射，未知值拒绝或待配置 |
| 标本预计信息 | 通过SCH-007表达材料类型、来源和预计数量；不提前制造实际材料事实 |
| 关联检测 | 通过SCH-006表达独立分子病例、附属检测或多模态关系；关系冲突不覆盖病例身份 |
| 更新语义 | 外部版本按来源系统作用域单调检查；更新产生原始事实和本地处理结果，不改写历史 |
| 取消语义 | 取消请求是命令入口；已形成下游事实时进入业务终止评估，不删除下游事实 |
| 成功技术应答 | 返回接收身份、幂等回执、处理状态和关联标识；不承诺病例已建立 |
| 业务应答 | 返回申请已接收、已归并、待核对、已建立病例或已隔离等规范化结果 |
| 错误 | ERR-001–016；错误返回稳定代码、处理方向和是否可重试 |
| 重试/补偿 | 技术可恢复失败可按P09-PARAM-004/005引用重试；业务冲突转人工归并和对账 |
| 事件 | EVT-001、EVT-002；取消/冲突可形成EVT-021治理事实 |
| 需求追溯 | REQ-0001–0010、0015–0019；AC对应申请、身份和幂等验收 |

## 3. P12-HIF-002：医嘱、收费和申请关联入站

| 契约项 | 规定 |
|---|---|
| 来源系统 | 收费/医嘱适配器；具体医院系统待配置 |
| 业务目的 | 提供医嘱、收费或退费关联上下文，不把收费状态当作诊断、标本或报告事实 |
| 请求Schema | SCH-001、004、005、020 |
| 必填 | 来源系统、消息身份、外部申请或病例身份、外部版本、发生时间和载荷摘要 |
| 条件必填 | 收费变更需有收费业务版本；医嘱关联需有医嘱外部身份；退费或取消需有原因和原关联 |
| 映射规则 | 医院字段待接入配置；规范化字段只表达关联类型、外部身份、版本、状态语义和时间，不接收未定义扩展列 |
| 幂等 | 来源+消息+外部业务身份+版本+摘要；相同身份不同摘要进入冲突 |
| 本地入口 | 调用申请/病例关联能力或形成外部事实待核验记录；不直接写材料、诊断或报告聚合 |
| 成功技术应答 | 接收身份、幂等回执、处理状态 |
| 业务应答 | 关联已记录、待核验、冲突或拒绝；不返回“诊断成功” |
| 错误/补偿 | ERR-001–006、012、016、069–074；技术失败可重试，业务冲突由MOD-012治理 |
| 事件/对账 | EVT-020或EVT-021；所有外部关联保留对账证据 |
| 需求追溯 | REQ-0063–0069、0088–0107；参数只引用P09编号 |

## 4. P12-HIF-003：外部结果和医学依据入站

| 契约项 | 规定 |
|---|---|
| 来源系统 | LIS、HIS/EMR或外送机构适配器；外部机构和系统名称待接入配置 |
| 业务目的 | 接收外部检测结果、外部报告、外部文件或医学依据，形成外部事实并进入本地核验 |
| 请求Schema | SCH-001、020、027、014；分子结果可引用SCH-028但不表示本地运行 |
| 必填 | 外部机构身份、外部任务身份、外部结果/报告版本、来源消息身份、原文或文件引用、载荷摘要、外部发生时间或接收时间 |
| 条件必填 | 外部文件存在时必须有文件身份和摘要；结果关联病例或材料时必须有可核验的外部关联；医学核验确认时必须有实际操作者和依据 |
| 外部事实 | 保留外部机构、外部版本、原文/文件引用、来源验证状态和本地核验状态；不写成本地设备运行、质控或有效结果 |
| 本地核验 | 先完成来源、文件和身份核验，再由有权限责任人确认可引用的医学依据或有效结果 |
| 成功技术应答 | 返回接收身份和待核验状态；不承诺已进入正式报告 |
| 业务应答 | 外部事实已接收、待核验、已核验、隔离或拒绝 |
| 错误/补偿 | ERR-049–060、067、068；完整性失败隔离，重复同版本返回原接收事实 |
| 事件 | EVT-004、EVT-013；核验完成后由主责任模块形成后续事实 |
| 需求追溯 | REQ-0048–0049、0050–0054、0062；AC要求外部结果不可伪装成本地执行 |

## 5. 入站字段映射模板

下表的“外部字段”刻意不填写具体医院字段名；接入项目必须在适配器配置中填入实际字段、代码系统和版本，并保留原始字段。

| 外部字段 | 规范化字段 | 外部含义 | 规范化含义 | 必填/条件必填 | 类型 | 代码系统 | 空值/冲突规则 | 敏感等级 |
|---|---|---|---|---|---|---|---|---|
| 接入项目配置 | source_system_code | 来源系统标识 | 来源命名空间 | 必填 | ControlledCode | 接入配置 | 缺失拒绝 | 中 |
| 接入项目配置 | source_message_identity | 消息身份 | 入站幂等身份 | 必填 | ExternalIdentifier | 来源系统 | 重复同摘要重放，不同摘要冲突 | 中 |
| 接入项目配置 | source_message_version | 消息版本 | 外部消息版本 | 必填 | VersionNumber | 来源系统 | 缺失隔离 | 中 |
| 接入项目配置 | external_business_identity | 外部申请/任务/报告身份 | 外部业务标识 | 条件必填 | ExternalIdentifier | 外部系统 | 缺失按接口类型拒绝或待人工 | 中至高 |
| 接入项目配置 | patient_external_reference | 外部患者引用 | 患者外部上下文 | 条件必填 | ExternalIdentifier | 医院身份域 | 不以姓名判定；冲突待核验 | 高 |
| 接入项目配置 | visit_external_reference | 外部就诊引用 | 就诊外部上下文 | 条件必填 | ExternalIdentifier | 医院就诊域 | 不能替代本地病例 | 高 |
| 接入项目配置 | pathology_modality_code | 外部病理类型代码 | 规范化病理类型 | 申请必填 | ControlledCode | 医院/受控配置 | 未映射拒绝或隔离 | 高 |
| 接入项目配置 | external_business_version | 外部业务版本 | 更新/报告/结果版本 | 更新和结果必填 | VersionNumber | 来源系统 | 旧版本不覆盖新版本 | 高 |
| 接入项目配置 | external_occurred_at | 外部发生时间 | 外部业务时间 | 条件必填 | UtcInstant/LocalBusinessDate | 来源时区 | 不等同接收时间 | 中 |
| 接入项目配置 | payload_reference | 原始报文或文件引用 | 可追溯原始事实 | 消息必填 | FileReference | 文件能力 | 不可打开则隔离 | 中至高 |
| 接入项目配置 | payload_digest | 载荷摘要 | 幂等和完整性依据 | 消息必填 | BinaryDigest | 摘要算法待确认 | 不一致冲突 | 中 |

## 6. 入站安全和审计

认证主体、服务主体、来源系统、接收时间、授权结果、目标对象和处理结果由可信系统上下文形成。客户端提供的外部发生时间、来源消息身份和业务说明必须标记为外部输入，不能替代实际操作者。患者身份冲突、错配、外部结果版本不一致和申请取消先到均产生可追溯治理或对账事实。
