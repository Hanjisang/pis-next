# P12 医院出站接口契约

文档状态：P12已基线化
正式出站接口：P12-HIF-004至007，共4项。出站载荷使用规范化Schema，目标系统字段和协议由适配器配置；本地事实、事件、投递、技术应答、外部业务确认和对账独立保存。

## 1. 出站共性顺序

```text
本地业务事实
→ P10-EVT事实事件
→ 出站事件和投递身份
→ 传输尝试
→ 外部技术应答
→ 外部业务确认
→ 对账
→ 重试、补偿或人工关闭
```

外部失败不得回滚本地申请、材料、有效结果、诊断或报告事实。出站幂等身份至少包含目标系统、业务事件身份、具体对象版本和载荷摘要；撤回、更正、补充和重新签发是独立业务事件，不能用旧事件覆盖。

## 2. P12-HIF-004：申请、病例和标本状态出站

| 契约项 | 规定 |
|---|---|
| 触发事实 | P10-EVT-002病例建立、P10-EVT-003标本接收，以及经确认的业务进度事实 |
| 来源模块/聚合 | MOD-001、MOD-002；AGG-001/002/003；出站由MOD-011承接 |
| 请求Schema | SCH-021、032、005、007、009 |
| 固定版本 | 病例版本、标本身份、交接身份和事件版本；不得发送“当前状态”而无版本上下文 |
| 目标系统 | HIS/EMR或医院指定目标；具体系统待配置 |
| 投递状态 | 待发送、已尝试、技术接收、业务待确认、业务已生效、受阻、对账差异、人工关闭；这些是出站记录状态，不是内部31个状态机的原样暴露 |
| 幂等身份 | target_system_code + event_identity + subject_identity + subject_version + payload_digest |
| 顺序 | 同一目标、同一业务主体按事件发生序列和版本检查；迟到消息进入对账，不静默覆盖 |
| 技术应答 | 仅确认传输层或接收层结果 |
| 业务确认 | 目标系统对申请、病例或标本业务生效的确认；缺失不改变本地事实 |
| 补偿 | 技术可恢复错误引用P09-PARAM-004/005；业务冲突转P10-MOD-012和对账 |
| 追溯 | EVT-002/003/019/020；REQ-0063–0065；P10-TXN-014 |

## 3. P12-HIF-005：病理进度和收费关联出站

| 契约项 | 规定 |
|---|---|
| 触发事实 | 业务进度、医嘱或收费关联事实经本地确认后形成出站事件 |
| 载荷 | SCH-032和明确的申请、病例、材料或关联引用；不复制诊断正文、完整患者资料或内部表名 |
| 状态映射 | 内部状态→规范化外部业务状态→医院适配状态；不同病理类型可使用不同映射；不可映射进入隔离和对账 |
| 幂等和版本 | 目标+事件+关联对象版本+摘要；同载荷重放返回首次投递结果，不同载荷冲突 |
| 技术/业务结果 | 传输成功、目标接收、业务生效、对账一致分层记录 |
| 错误 | ERR-069–074；目标不可用可重试，版本/业务冲突需人工处理 |
| 追溯 | EVT-019/020；REQ-0063、0066–0069；P10-TXN-014 |

## 4. P12-HIF-006：报告版本和PDF调阅出站

| 契约项 | 规定 |
|---|---|
| 触发事实 | 报告签发、补充、更正、撤回、重新签发，或经授权的报告/文件调阅请求 |
| 报告载荷 | report_lifecycle_identity、具体report_version_identity、report_version_number、report_event_kind_code、clinical_validity_code、composition_references |
| 文件载荷 | file_identity、file_version_identity、format_code、digest、size_measurement和受控访问引用；PDF不是唯一医学事实 |
| 版本保护 | 组成报告和综合报告各自固定版本；外部回传引用具体版本；重新生成PDF形成新文件版本或身份，不修改医学报告版本 |
| 撤回语义 | 撤回是独立报告生命周期事件，外部未支持撤回时形成对账差异和人工处置，不删除本地事实 |
| 技术/业务结果 | 外部技术接收、外部业务生效、撤回生效、对账一致分别记录 |
| 幂等 | target + report_version_identity + report_event_identity + file_version_identity + digest |
| 错误 | ERR-063–072；报告版本冲突、文件完整性失败和外部业务拒绝不可静默重试 |
| 追溯 | EVT-015/016/019/020；REQ-0059–0062；P10-TXN-008/014 |

## 5. P12-HIF-007：接口纠错、撤回和对账通知出站

| 契约项 | 规定 |
|---|---|
| 触发事实 | 受控纠错、报告撤回/重签、外部差异处理、业务确认结果或人工关闭 |
| 载荷 | SCH-026、031、032；包含原事件、当前版本、纠错原因、影响范围、责任和对账引用，不暴露内部外键 |
| 幂等 | governance_identity + original_event_identity + new_event_identity + target_system_code |
| 顺序 | 新纠错事件不能早于原业务事实；外部迟到或乱序必须保留并进入差异队列 |
| 技术应答 | 只表示通知到达或被接收 |
| 业务确认 | 目标系统确认纠错、撤回或新版本生效；未确认保持待处理 |
| 补偿 | 可恢复传输失败引用参数；业务拒绝、目标不支持或版本冲突形成差异和人工入口 |
| 追溯 | EVT-016/019/020/021；REQ-0061、0066–0069、0070–0087 |

## 6. 医院外部状态回传映射

| 层次 | 语义 | 约束 |
|---|---|---|
| 内部状态 | P08对象状态机的正式状态 | 不原样暴露给医院；由主模块守卫产生 |
| 规范化外部业务状态 | 接收、处理中、待核验、已完成、已撤回、受阻、对账差异等业务语义 | 不替代内部状态；版本和来源必须保留 |
| 医院适配状态 | 目标系统字段和代码 | 接入配置；未知或无法映射时拒绝、隔离或对账 |
| 业务确认 | 外部目标实际生效 | 独立于技术应答和本地事实 |

## 7. 报告回传门禁

报告生命周期、具体报告版本、当前临床有效版本关系、PDF呈现文件、结构化报告内容、签发事实、投递事实、外部技术接收、外部业务生效、撤回生效和对账均单独引用。不得只发送病理号和“当前报告”；综合报告不得覆盖组织、细胞或分子组成报告。
