# P12 接口安全、责任与审计上下文契约

文档状态：P12已基线化
边界：P12声明每个高风险API的安全和审计输入，不建立P14完整角色权限矩阵。

## 1. 身份与责任层次

| 身份/责任 | 契约字段 | 来源 | 是否可成为医学责任 | 审计要求 |
|---|---|---|---|---|
| 实际认证主体 | authenticated_subject | 可信认证上下文 | 可以，仍需业务权限和任务责任 | 认证方式、时间、撤销状态 |
| 业务责任人 | responsible_party | 主责任模块和任务 | 可以，按业务规则 | 任务、对象范围、操作结果 |
| 代理身份 | actual_operator、delegated_responsible_party、delegation_identity | 代理关系 | 代理不改变被代理责任；按P14规则 | 依据、起止、范围、撤销和事后复核 |
| 服务身份 | service_subject | 可信服务上下文 | 不得成为人工医学签发人 | 服务调用、凭证上下文和操作结果 |
| 设备身份 | device_subject | 设备适配器上下文 | 不得确认医学有效性或签发 | 设备、任务、运行、原始载荷 |
| 外部系统身份 | source_system_code、target_system_code | 适配器和消息上下文 | 不得替代本地责任 | 来源、目标、版本、技术/业务应答 |
| 第二人复核主体 | second_review_subject | 可信授权上下文 | 可完成复核，不替代首责 | 复核内容、结论、时间和关联 |

## 2. 统一可信审计上下文

每个命令、医院接口、事件消费、文件访问和高风险查询使用`P12-SCH-023`，至少记录：authenticated_subject、service_subject、proxy_identity、source_system_code、received_at、authorization_outcome、target_subject、operation_code、processing_outcome、correlation_identity、causation_identity、expected_version、current_version、sensitivity_code和failure_reason。客户端只能提供业务原因、外部发生时间、来源消息标识和申请说明；不能自报实际操作者、授权结果或接收时间。

## 4. 普通接口和服务身份

普通申请接收、设备回执和文件传输可以由服务身份发起，但服务身份必须绑定来源系统、适配器、业务目标、原始消息和可信接收时间。服务身份只能调用相应应用端口；它不能直接修改聚合、确认诊断/报告、确认分子医学有效性或批准销毁。

## 5. 患者和材料最小化

接口和事件默认使用患者/就诊外部引用、业务快照摘要和本地病例关系，不复制完整患者身份。材料接口只传必要的身份、来源、用途、责任、数量和剩余量。诊断正文、报告正文、原始设备载荷和外部文件按任务责任、对象范围和数据范围授权，事件不默认携带全文。

## 6. 审计事件边界

审计与异常、质量事件、诊断记录、报告版本、材料事实和投递记录分开。审计至少覆盖：认证、授权拒绝、代理使用、强认证、第二人复核、身份/来源纠错、报告签发/撤回/重签、结果有效性确认、外部核验、文件访问/导出、销毁、恢复、重放、人工补偿和对账关闭。审计只追加或形成受控治理事实，不由普通业务更新删除。
