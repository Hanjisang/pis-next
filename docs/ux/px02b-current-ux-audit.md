# PX02B 当前产品体验审查

## 1. 范围与结论

本审查针对 PX02B 的生产工作台、病例历史、诊断工作站、数字切片、登记、取材、查询和归档入口。审查重点是高频操作路径、业务语言、病例上下文、历史可追溯性和 1366×768 桌面可用性。

结论：核心页面不需要新增病理业务模型，但需要把 Histology 的双工作视角收敛成阶段事实工作台，并把历史、患者既往病理和病例深链提升为跨工作区能力。

## 3. 主要问题与处置

1. Histology 同时显示旧的生产状态语义和阶段事实。已把阶段队列作为用户主视图，`PENDING/IN_PROGRESS/COMPLETED` 不再作为用户主标签；`COMPLETED` 仅保留为“已完成”队列的内部查询值。
2. 当前 Case 的扫码动作曾依赖全局玻片队列，存在加载时序和跨病例匹配风险。病例制片页现在优先从当前 Case 材料树定位玻片，再写入完成事实。
3. 业务历史曾把诊断摘要 digest 作为原文显示，导致业务用户看到内部字符串并在 1366 宽度下产生横向溢出。现在转换为“诊断内容已修改，历史记录已保留”等业务语言，并增加长文本换行保护。
4. 病例中心、诊断工作区和登记页曾直接显示申请项目内部码。正式业务页面现在显示业务类型和“已按配置映射”等业务语言；内部码仅留在配置、API 和测试边界。
5. 报告列表返回顺序可能是最新在前，但版本编号必须保持 `R001` 为报告 1、`R002` 为报告 2。诊断工作区现在按报告编号/签发顺序计算显示标签，保留最新在前的阅读顺序。

## 4. 未纳入本轮

真实 HIS/LIS/EMR、厂商扫描仪、厂商打印机、CA/电子签章、生产部署、历史数据正式迁移和 Pilot 仍属于 Site Integration/Production Readiness，PX02B 不以本地 Mock 证据替代这些验证。
