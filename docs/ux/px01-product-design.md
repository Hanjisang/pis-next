# PIS V2 PX01 产品体验设计

状态：PX01 实现完成，进入验证收口

基线：`main`，PX01 变更尚未提交

## 1. 产品目标

PX01 将 PIS V2 从“按模块完成正向流程”调整为病理科日常生产工作区：

1. 登录后先看到当前岗位真正要处理的工作项；
2. 任意病例、标本、蜡块、玻片和报告都可以回到统一病例中心；
3. 病例历史使用病理业务语言呈现，而不是直接暴露审计表；
4. 诊断医生在一个 Diagnosis Workspace 内查看证据、开技术医嘱、处理结果、预览和签发；
5. 技术人员围绕玻片完成任务，同时可以记录脱水、包埋、切片、染色、封片的轻量事实；
6. 数字切片由可替换的阅片器容器承载，不把 WSI 服务或厂商 SDK 放入核心领域。

## 2. 页面信息架构

一级任务入口仍由登录身份、角色和权限过滤：工作台、登记、取材、制片、诊断、冰冻、技术医嘱、报告、归档借阅、查询、质控统计、配置、系统管理。

病例中心不是新的业务模块，而是统一查询入口：

```text
工作台 / 查询 / 任意工作区
        ↓
病例中心 /v2/cases/:caseId
        ├─ 材料与制片
        ├─ 业务历史
        ├─ 责任链
        └─ 报告历史
```

材料、责任链和技术医嘱目标不作为一级用户导航。

## 3. Personal Workbench

工作台按当前身份组合真实队列，不使用功能入口九宫格。队列入口必须直接落到对应工作区：

| 岗位 | 首要工作项 |
| --- | --- |
| 登记员 | 待登记申请、待补充、异常申请、今日登记 |
| 取材医生 | 待取材、补充取材、冰冻 |
| 技术人员 | 待制片、技术医嘱、冰冻、技术过程事实 |
| 诊断医生 | 待初诊、待复诊、待审核、技术结果返回 |
| 管理人员 | 仅在获得权限时进入配置、质控和统计 |

页面按钮使用认证权限与后端查询结果中的 available actions；前端不以角色名称替代业务授权。

## 4. Case 360 与 Timeline

`GET /api/v2/case-workspaces/{caseId}` 是只读工作区 Query。它组合既有病例、材料、取材、责任、技术医嘱、数字切片、报告和审计/业务事实，返回：

- 统一病例 Header；
- Specimen → Block → Slide → DigitalSlide 材料树；
- 取材和技术医嘱摘要；
- 初诊、复诊、审核责任链；
- 报告状态、签发人、撤回和补充关系；
- 业务时间线。

时间线在 Query 层映射为“完成登记、开始取材、完成制片、接诊病例、开立技术医嘱、签发报告”等业务语言。对象历史入口使用同一时间线，并支持按对象 ID过滤。

## 5. 工作区设计

### 5.1 登记

保留正式 Registration Command，单页完成患者/就诊、申请、业务类型和多个标本。支持新增、复制、删除、排序；会诊可以没有本院标本。登记完成后立即展示新病理号和病例中心入口。

### 5.2 取材

保留 Case 级 Grossing Query 和现有 Block Commands。页面按病例切换多个标本，快速输入蜡块编号、Enter新增、复制上一蜡块、打印/补打、软删除和完成取材。统一 CaseHeader 提供病例中心、材料进度和当前责任入口。

### 5.3 Histology / Production

主工作台主人仍然是 Slide。已有打印、扫码完成、批量完成和补打保持不变；PX01 增加 `material_process_fact` 查询/命令，仅记录：

- `startedAt`；
- `completedAt`；
- `operator`；
- 可选设备/批次引用；
- 异常类型和说明。

状态由时间事实推导，不引入复杂技术状态机。五个阶段为：脱水、包埋、切片、染色、封片。

### 5.4 Diagnosis Workspace

诊断编辑器仍复用 `DiagnosisTemplate`、结构化数据、责任链、TechnicalOrder 和 Report Query。新增统一 CaseHeader 和 Evidence 区：

- 标本、蜡块、玻片和数字切片保持可见；
- 点击数字切片在当前工作区展开阅片容器；
- 技术结果在右侧责任/医嘱区显示；
- 固定底部操作条继续由后端 actions 决定；
- 诊断、预览、签发、撤回、补充和历史保持同一病例上下文。

### 5.5 DigitalSlide Viewer

`V2ImageViewer` 是前端 Adapter 容器，提供缩放、平移、还原、全屏、缩略导航区域、多个数字切片切换和外部引用入口。它可承接普通图片、WSI Viewer 或医院数字病理平台引用。

本轮不实现 Tile Server、WSI 金字塔、扫描仪协议、AI、标注和测量。

### 5.6 Frozen / Technical / Report

- Frozen 使用统一 CaseHeader，轮次仍复用 `FrozenRound` 和统一 Specimen/Grossing/Block/Slide/Diagnosis/Report；
- TechnicalOrder 工作台按待处理、处理中、待录结果、已完成组织，结果返回后直接可打开病例中心或诊断工作区；
- Report History 展示报告性质、状态、签发人、签发时间、撤回原因和补充关系，不覆盖历史报告。

## 6. 设计系统

PX01 统一使用现有 Design Tokens，并增加病例 Header、时间线、阅片器、工作台面板、空状态、状态标签和响应式布局样式。目标分辨率为 `1920×1080` 和 `1366×768`，默认适度紧凑，颜色只表达成功、警告、错误和当前责任等语义。

## 7. 架构约束

- Core Domain modified files 目标：`0`；
- 不新增 `CaseStatus`、`BusinessRecord`、`FrozenXXX`、`DiagnosisTask`、`ReportVersion` 等平行模型；
- Case 360、Timeline、Search 和 Viewer 均在查询/前端边界实现；
- Histology 事实表是 PX01 的轻量生产事实支撑，不是复杂状态机，不替代 Slide 生命周期；
- 不接入真实 HIS/LIS/EMR、厂商设备、CA、医院 Pilot 或历史数据迁移。
