# PIS V2 UX 原则

## UX01-PR-01 任务优先

一级导航、工作台和页面标题必须围绕登记、取材、制片、诊断、冰冻等用户任务组织，不按数据库表或领域类组织。

## UX01-PR-02 业务语言

界面只使用病理科可理解的术语。内部聚合、投影、上下文代码、责任单元和消息机制不得作为用户标签。

## UX01-PR-03 单一主工作区

一个主要任务应尽量在一个工作区完成。复杂上下文在工作区内切换，短操作使用侧栏或确认层，不把核心任务拆成连续弹窗。

## UX01-PR-04 下一步明确

页面首屏必须说明当前对象、当前进度、待办和主操作。成功、失败、冲突与阻塞都必须说明下一步动作。

## UX01-PR-05 生产效率

桌面端优先；默认使用适度紧凑表格。高频操作支持批量、扫码、复制和键盘操作。`Ctrl+K` 打开全局查询，`Ctrl+S` 保存诊断。

## UX01-PR-06 医疗安全

界面不得静默丢弃临床数据，不得通过乐观提示掩盖后端失败，不得绕过权限与责任链。报告签发、撤回、补充和材料作废保留原业务语义。

## UX01-PR-07 可访问性

表单必须有可访问名称；键盘焦点必须可见；状态不能只靠颜色表达；错误使用 `role=alert`，持续性操作结果使用 `role=status`。

## UX01-PR-08 性能边界

工作区优先使用面向任务的查询接口。前端不通过大量串行请求重建领域状态，也不把全部病例数据放入全局状态容器。
