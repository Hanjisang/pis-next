# PIS V2 信息架构

文档状态：待业务确认
文档版本：PX03B
最后更新：2026-08-11
相关基线：PIS V2 PX03B Workbench × Case Center 双轴交互架构

## 1. 核心交互轴

PIS V2 只建立两个核心业务入口：

| 入口 | 关注对象 | 回答的问题 |
| --- | --- | --- |
| 工作台 | 人 | 我现在要处理什么？ |
| 病例中心 | 病例 | 这个病例现在是什么情况，以及围绕它还能做什么？ |

全局搜索是第三个全局能力，不是第三条业务轴：用户主动找到病例后，统一进入病例中心。

## 2. 一级导航

普通用户正式导航只有：

- 工作台；
- 全局搜索（顶栏 `Ctrl/Cmd + K`）；
- 用户头像。

登记、取材、制片、冰冻、技术医嘱、诊断、报告、归档和质控不作为普通用户一级菜单，而是由工作台项目或病例中心当前操作进入。系统管理和配置从管理员头像入口进入，视觉上与业务 PIS 分离。

## 3. 工作台

工作台是高密度、队列优先的人的工作中心，按权限和数据范围显示：

- 我的工作：待初诊、待复诊、待审核、新技术结果、撤回待处理等；
- 生产来源队列：常规制片、细胞制片、冰冻制片、技术医嘱、待完成玻片、异常 / 返工；
- 待接诊病例；
- 我登记的病例。

跨病例联动只在工作台产生。工作项必须携带病例中心深链；点击工作项后，病例中心根据 `focus` 自动定位当前业务上下文。工作完成后由当前工作台队列决定下一项，不按 `caseId + 1` 推断下一病例。

## 4. 病例中心

病例中心是单病例工作区，不是业务模块菜单。顶部固定病例上下文，至少持续显示：

- 病理号、患者、性别/年龄（当前数据没有时明确显示待补充）；
- 病理类型、来源科室、送检医生、登记时间；
- 当前环节、当前处理人、报告状态。

首屏通过病例摘要、材料摘要、生产摘要、诊断摘要、报告摘要和最近动态回答：谁、什么病例、为什么送检、有什么材料、做到哪里、谁在处理、报告是否签发。

病例级视图只保留：

1. 概览；
2. 材料；
3. 诊断与阅片；
4. 报告；
5. 病例记录。

材料树支持 `Specimen → Block → Slide → DigitalSlide`、细胞直接玻片以及外来材料的扩展表达，不强制所有病例具备完整组织学层级。技术医嘱作为病例内摘要/面板，冰冻仅在存在 `FrozenRound` 时出现。

## 5. 双向联动

| 来源 | 进入病例中心后的上下文 |
| --- | --- |
| 待登记/登记完成 | 登记或病例概览 |
| 待取材 | 取材上下文 |
| 常规/细胞/冰冻制片 | 制片上下文 |
| 技术医嘱/新技术结果 | 技术结果上下文 |
| 待初诊/待复诊/待审核 | 诊断与阅片上下文 |
| 报告撤回/待签发 | 报告上下文 |
| 全局搜索 | 病例概览或被搜索对象上下文 |

病例中心根据 `BusinessType`、病例事实、当前权限和可执行动作只显示有权操作。权限由后端授权决策和 `availableActions` 约束，前端不以 `roleCode` 代替授权。

## 6. 领域边界

本架构只新增查询投影、前端上下文和深链组合，不新增持久化 `Task`、`WorkItem`、`WorkflowInstance` 或 `StepInstance`。工作台待办由病例、标本、玻片、技术医嘱、诊断、报告和审计等业务事实重新投影。

脱水、包埋、切片、染色和封片保留为可选技术记录，不作为默认队列、病例生命周期或一级导航。

## 7. 验收基线

- 登记员登录后进入工作台，可从工作台进入登记；登记完成后的病例通过病例中心继续追踪；
- 技术员可在工作台看到按业务来源的制片队列，点击任一工作项进入病例中心制片上下文；
- 医生可在工作台看到待接诊、诊断、审核和新技术结果，点击后进入病例中心诊断上下文；
- 全局搜索结果统一落到病例中心；
- 所有病例中心子工作区始终提供“← 工作台”和固定病例头；
- 浏览器验收覆盖普通用户导航收敛、Workbench → Case Center、Case Center 当前业务上下文和 Global Search → Case Center。
