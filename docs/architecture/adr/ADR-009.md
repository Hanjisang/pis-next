# ADR-009：审计、质量事件和受控纠错

状态：已决定
日期：2026-08-06
背景：P10需要在不改变P04–P09确认结论的前提下形成可追溯、可验证且不泄漏后续实现的系统架构。
架构驱动：P05-INV-040–048、P08-SM-019/020/030、P10-DRV-001/010
候选方案：万能日志；删除错误记录；质量事件覆盖业务事实；全局纠错服务直接写入所有模块
决策：选择审计、异常、质量、纠错和恢复校验分开，治理模块协调，主责任模块形成新业务事实。
理由：医疗责任、影响范围和恢复证据需要不同生命周期；集中写入会破坏聚合边界。
正面影响：原值、异常、责任、校验和新版本可追溯；恢复后能重新应用冻结和销毁事实。
负面影响：增加模块边界、协调记录、观测和治理能力；P11、P12、P14、P25和P27需要继续细化实现边界。
风险：审计缺失、质量关闭没有影响结论、纠错覆盖原值或恢复直接放行。
缓解措施：以主责任模块、业务事件、幂等、审计、受控纠错、对账和关闭审查保护边界；所有未确认参数进入后续确认，不在P10硬编码。
适用边界：P09-REQ-0061–0087；P08治理状态机；P10-MOD-012–014。
重新评估条件：法规或恢复治理要求改变时复评。
需求追溯：P10-RULE-009/016/017；P10-DRV-005/010/011
