# ADR-003：事务和一致性策略

状态：已决定
日期：2026-08-06
背景：P10需要在不改变P04–P09确认结论的前提下形成可追溯、可验证且不泄漏后续实现的系统架构。
架构驱动：P05-INV-001–070、P10-TXN-001–015、P10-DRV-004/010
候选方案：所有协作使用单一强一致；跨外部系统分布式事务；聚合内强一致加跨边界最终一致
决策：选择聚合内本地强一致；同模块多聚合受控协调；跨模块可靠事件最终一致；外部系统使用投递、回执、对账和补偿。
理由：患者安全、身份、来源、版本和报告事实需要即时守卫，但设备、文件和外部机构不可要求共同提交。
正面影响：故障可局部隔离，事实不因外部失败回滚，P25可验证重复、乱序、并发和补偿。
负面影响：增加模块边界、协调记录、观测和治理能力；P11、P12、P14、P25和P27需要继续细化实现边界。
风险：聚合内不变量被异步化、外部结果被当作本地事实或协调无完成条件。
缓解措施：以主责任模块、业务事件、幂等、审计、受控纠错、对账和关闭审查保护边界；所有未确认参数进入后续确认，不在P10硬编码。
适用边界：P05-INV-037–040、P05-INV-045–048；P09-REQ-0055–0087；P10-TXN-001–015。
重新评估条件：不变量归属、法规或外部业务确认语义改变时复评。
需求追溯：P10-RULE-006/007/008/021；P10-DRV-005/008/010
