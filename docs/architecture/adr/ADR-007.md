# ADR-007：外部系统防腐层

状态：已决定
日期：2026-08-06
背景：P10需要在不改变P04–P09确认结论的前提下形成可追溯、可验证且不泄漏后续实现的系统架构。
架构驱动：P09-REQ-0042–0049、0055–0069、P10-EXT-001–014
候选方案：外部系统直接修改核心事实；每个外部系统共享一套语义；统一集成模块加防腐映射
决策：选择按系统和能力建立外部适配器，统一处理身份、编码、状态、时间、版本、错误、原始消息和对账。
理由：医院系统、设备和外送机构事实归属不同，核心领域不能被外部语义污染；适配器隔离协议变化。
正面影响：外部失败、迟到、重复和乱序可局部处理；P12可在不改核心模型的情况下定义契约。
负面影响：增加模块边界、协调记录、观测和治理能力；P11、P12、P14、P25和P27需要继续细化实现边界。
风险：外部状态直接写业务事实；技术回执被当作业务确认；无原始消息和对账证据。
缓解措施：以主责任模块、业务事件、幂等、审计、受控纠错、对账和关闭审查保护边界；所有未确认参数进入后续确认，不在P10硬编码。
适用边界：P05-INV-037–040/063/069；P10事件和上下文；P09未确认重试/对账参数。
重新评估条件：外部系统能力或医学责任归属发生变化时复评。
需求追溯：P10-RULE-013/016；ADR-003/004
