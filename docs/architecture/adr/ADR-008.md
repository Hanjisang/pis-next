# ADR-008：安全、授权、代理和强认证

状态：已决定
日期：2026-08-06
背景：P10需要在不改变P04–P09确认结论的前提下形成可追溯、可验证且不泄漏后续实现的系统架构。
架构驱动：P09-REQ-0061–0069、0075–0087、P05-INV-041–044
候选方案：共享角色；系统管理员万能授权；服务身份承担人工责任；权限全部硬编码
决策：选择认证、组织上下文、角色、对象范围、任务责任、代理、临时授权、强认证和复核分层。
理由：P10需要提供安全边界但不冻结P14详细矩阵；高风险操作必须可识别、可复核、可审计。
正面影响：可以适应医院组织差异，阻断越权、共享账号和服务冒充人工。
负面影响：增加模块边界、协调记录、观测和治理能力；P11、P12、P14、P25和P27需要继续细化实现边界。
风险：代理没有有效期；紧急授权无事后复核；审计可被普通业务操作修改。
缓解措施：以主责任模块、业务事件、幂等、审计、受控纠错、对账和关闭审查保护边界；所有未确认参数进入后续确认，不在P10硬编码。
适用边界：P05-INV-041–044；P09安全需求；P10-MOD-013。
重新评估条件：法律、组织或高风险业务范围改变时复评。
需求追溯：P10-RULE-014/015/023；P10-DRV-009
