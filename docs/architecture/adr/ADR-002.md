# ADR-002：模块与聚合归属

状态：已决定
日期：2026-08-06
背景：P10需要在不改变P04–P09确认结论的前提下形成可追溯、可验证且不泄漏后续实现的系统架构。
架构驱动：P05-AGG-001–018、P10-DRV-002/003/004
候选方案：按病理类型复制聚合；一个万能病例模块；按正式聚合唯一主归属
决策：选择15个逻辑模块和18个聚合唯一主归属；共性模块共享能力，组织、冰冻、细胞、分子、外送和多模态保持专用路径。
理由：聚合是业务事实和不变量边界；唯一写入归属保护历史和责任，也避免每个聚合机械拆成服务。
正面影响：63个对象、31个状态机和107项需求均可挂到主责任模块；未来拆分不会改变业务归属。
负面影响：增加模块边界、协调记录、观测和治理能力；P11、P12、P14、P25和P27需要继续细化实现边界。
风险：模块跨边界直接修改、通用模块承载所有事实或类型路径强行合并。
缓解措施：以主责任模块、业务事件、幂等、审计、受控纠错、对账和关闭审查保护边界；所有未确认参数进入后续确认，不在P10硬编码。
适用边界：P05对象/聚合、不变量；P06流程；P08状态机；P09需求。
重新评估条件：对象责任或跨聚合协作证据发生结构性变化时复评。
需求追溯：P09-REQ-0001–0087；P10-MOD-001–015；P10-RULE-004/011
