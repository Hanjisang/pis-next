# ADR-006：领域状态机与任务编排

状态：已决定
日期：2026-08-06
背景：P10需要在不改变P04–P09确认结论的前提下形成可追溯、可验证且不泄漏后续实现的系统架构。
架构驱动：P08-SM-001–031、P07异常、P10-DRV-003/010
候选方案：工作流引擎作为唯一事实；每个待办都建状态机；领域状态机与任务协调分离
决策：选择P08领域状态机由拥有模块维护，任务协调只提供待办、通知、超时、重试和人工接管。
理由：领域状态表示对象事实，任务表示责任协调，混合会让外部任务状态覆盖医学事实。
正面影响：31个状态机有明确归属，局部任务失败可继续，P25能分别验证事实和待办。
负面影响：增加模块边界、协调记录、观测和治理能力；P11、P12、P14、P25和P27需要继续细化实现边界。
风险：任务完成直接推进无守卫的领域状态；通用编排器绕过授权或版本保护。
缓解措施：以主责任模块、业务事件、幂等、审计、受控纠错、对账和关闭审查保护边界；所有未确认参数进入后续确认，不在P10硬编码。
适用边界：P08状态机、P07异常；P09-REQ-0061–0069；P10模块边界。
重新评估条件：任务规模或跨机构协作出现独立故障隔离证据时复评组件边界，不改变事实归属。
需求追溯：P10-RULE-010/017；P08-SM-001–031
