# ADR-005：身份、编号、版本和历史

状态：已决定
日期：2026-08-06
背景：P10需要在不改变P04–P09确认结论的前提下形成可追溯、可验证且不泄漏后续实现的系统架构。
架构驱动：P05-INV-001–016/024–033、P08多类状态机
候选方案：用病例状态替代对象身份；复用业务编号；直接修改历史；全局事件溯源
决策：选择内部身份、业务编号、来源标识、版本和历史分别表达；以追加事实、不可变版本和受控纠错保护医疗历史。
理由：P05已确认对象独立生命周期，报告和材料必须保留来源；全局事件溯源会扩大复杂度，不能替代现有领域模型。
正面影响：对象和报告可纠错但不失去原值、责任和时间；外部标识不会冒充本地身份。
负面影响：增加模块边界、协调记录、观测和治理能力；P11、P12、P14、P25和P27需要继续细化实现边界。
风险：编号复用、版本覆盖、外部值写成内部事实或纠错删除历史。
缓解措施：以主责任模块、业务事件、幂等、审计、受控纠错、对账和关闭审查保护边界；所有未确认参数进入后续确认，不在P10硬编码。
适用边界：P09-REQ-0001–0020、0055–0060、0070–0087；P05-INV-001–016/024–048。
重新评估条件：新的法规保留要求或对象身份规则发生变更时复评。
需求追溯：P10-RULE-009/022/023；P10-DRV-001/002/005
