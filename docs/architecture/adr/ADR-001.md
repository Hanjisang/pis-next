# ADR-001：总体架构风格

状态：已决定
日期：2026-08-06
背景：P10需要在不改变P04–P09确认结论的前提下形成可追溯、可验证且不泄漏后续实现的系统架构。
架构驱动：P09质量属性、P10-DRV-004/008/011/013、AGG-001–018
候选方案：全面微服务；少量独立服务；边界明确的模块化单体
决策：选择边界明确的模块化单体，配合可靠事件/任务、文件与数字材料、集成、观测和恢复逻辑组件。核心业务模块保持同一业务运行边界，但禁止跨模块直接写入。
理由：当前没有足够独立伸缩、独立交付、安全域或故障隔离证据支持全面服务化；该方案降低跨外部一致性和运维复杂度，同时保留未来拆分条件。
正面影响：模块边界、聚合归属、事件和适配器边界清晰；可按证据评估独立组件。
负面影响：增加模块边界、协调记录、观测和治理能力；P11、P12、P14、P25和P27需要继续细化实现边界。
风险：模块间直接写入、容量增长或安全域隔离证据不足时，禁止先行拆分；由P25/P27提供证据。
缓解措施：以主责任模块、业务事件、幂等、审计、受控纠错、对账和关闭审查保护边界；所有未确认参数进入后续确认，不在P10硬编码。
适用边界：P04–P09全量；不改变P10模块和P11/P12阶段边界。
重新评估条件：出现明确独立伸缩、交付、安全域、故障隔离和数据归属证据，且最终一致边界可接受时复评。
需求追溯：P09-REQ-0088–0107；P10-RULE-002/003/019；P10-DRV-013/014
