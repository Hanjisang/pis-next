# ADR-004：领域事件及可靠投递

状态：已决定
日期：2026-08-06
背景：P10需要在不改变P04–P09确认结论的前提下形成可追溯、可验证且不泄漏后续实现的系统架构。
架构驱动：P05-INV-037–040、P08-SM-018、P10-EVT-001–021
候选方案：同步复制内部事实；每个状态转换都发布事件；可靠事件和受控任务协调
决策：选择由业务事实触发的不可变事件，使用事件身份、版本、消费去重、重试、受阻、补偿和对账能力。
理由：事件数量由跨模块责任和外部协作产生，不把状态机变成事件目录；本地事实与投递状态分离。
正面影响：可追踪跨模块协作、外部重试和人工重放，不重复产生申请、材料、诊断或报告。
负面影响：增加模块边界、协调记录、观测和治理能力；P11、P12、P14、P25和P27需要继续细化实现边界。
风险：事件没有来源版本、消费者幂等或人工关闭；重放覆盖新版本。
缓解措施：以主责任模块、业务事件、幂等、审计、受控纠错、对账和关闭审查保护边界；所有未确认参数进入后续确认，不在P10硬编码。
适用边界：P09-REQ-0055–0069；P10-EVT-001–021；P08-SM-018。
重新评估条件：事件量、目标系统或外部确认规则显著变化时复评。
需求追溯：P10-RULE-007/008/020；ADR-003、007
