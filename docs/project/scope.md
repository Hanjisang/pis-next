## 1. 范围说明

本文定义 PIS Next 第一版的建设范围。

本阶段只确认模块级边界，不定义详细业务规则、对象关系、流程、状态机、数据库表和页面字段。

---

## 2. 第一版目标用户

第一版主要面向医院病理科及相关系统协作人员。

包括：

- 病理登记人员；
- 标本接收人员；
- 取材医生或取材人员；
- 病理技术人员；
- 病理诊断医生；
- 病理审核医生；
- 冰冻业务人员；
- 数字切片扫描人员；
- 病理档案人员；
- 病理科管理人员；
- 系统管理员；
- 接口运维人员。

临床医生主要通过医院系统申请病理检查和查看报告，不作为第一版主要 PIS 工作站用户。

## 4. 第一版明确不在范围内

### OUT-PIS-001：AI自动诊断

第一版不实现 AI 自动诊断、自动签发或替代医生决策。

### OUT-PIS-002：耗材采购和供应链

第一版不实现采购计划、供应商管理、招投标、仓储供应链和财务结算。

### OUT-PIS-003：科研数据平台

第一版不建设独立科研数据库、队列研究平台或科研统计平台。

### OUT-PIS-004：互联网会诊结算

第一版不实现专家费用、支付、提现、分账和互联网结算。

### OUT-PIS-005：社交功能

第一版不实现帖子、评论、关注、收藏和社区。

### OUT-PIS-006：医院主数据平台

第一版只消费必要的医院主数据，不替代医院主数据管理平台。

### OUT-PIS-007：医院统一集成平台

第一版只建设 PIS 自身接口适配和可靠性能力，不替代完整医院集成平台。

### OUT-PIS-008：任意流程设计器

第一版不建设用户自行拖拽定义任意病理流程的低代码平台。

### OUT-PIS-009：真实医院生产对接

开发阶段不直接连接真实医院生产系统。

### OUT-PIS-010：真实患者数据

开发和自动化测试阶段不使用真实患者数据。

## 5. 第一版业务闭环

第一版必须至少形成以下完整闭环：

```text
病理申请
→ 病理登记
→ 标本接收
→ 取材
→ 蜡块
→ 脱水
→ 包埋
→ 切片
→ 染色
→ 数字切片
→ 诊断
→ 审核
→ 报告签发
→ 报告回传
→ 归档
```

同时支持：

```text
补取材
重脱水
重包埋
重切
重染
重扫
作废
撤回
更正
接口重试
```

## 6. 第一版范围判断原则

后续发现新需求时，按照以下原则判断是否进入第一版：

1. 是否直接影响患者安全；
2. 是否直接影响标本和报告追溯；
3. 是否属于病理核心业务闭环；
4. 是否是系统生产运行的必要条件；
5. 是否是医院接口可靠性的必要条件；
6. 是否可以通过配置而非新增模块解决；
7. 是否会显著增加第一版复杂度；
8. 是否可以推迟而不影响核心闭环。

不能满足核心必要性的需求，优先进入后续版本。

---

## 7. 范围变更规则

第一版范围发生变化时，必须：

1. 记录变更原因；
2. 评估患者安全影响；
3. 评估业务对象影响；
4. 评估流程和状态机影响；
5. 评估数据库影响；
6. 评估接口影响；
7. 评估测试范围；
8. 更新本文版本；
9. 更新项目总体计划；
10. 不得只修改代码而不更新范围文档。
