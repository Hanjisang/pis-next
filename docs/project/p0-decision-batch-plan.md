## 3. 分批原则

1. 先处理会改变核心业务对象身份、来源和追溯链的决策，再处理依赖这些身份的关系、诊断、技术、接口和配置决策。
2. 每个 P0 决策项只进入一个决策包；决策包的归类服务于确认顺序，不改变原始决策项编号和原始问题追溯。
3. 单个决策包控制在 5–10 项；DB-P0-01 历史上包含 8 项，当前有效 P0 为 7 项，另有 1 项已重分类为非 P0 原则/配置项；聚焦患者/就诊/申请/病例到容器、标本、蜡块和玻片的身份与来源链。
4. 候选方案、推荐方向和风险均为确认准备材料，所有结论必须由业务责任人确认后才能进入“已确认”。
5. 依赖关系是当前基于已完成文档建立的规划建议；若业务确认改变前置对象边界，必须回写影响的决策包和追溯关系。
6. 全项目业务决策和后续 P05 设计必须遵循业务信息灵活修改与受控纠错原则：允许合理纠错但不得无痕覆盖，系统管理权限与业务纠错权限必须区分，已形成下游事实须保留历史并评估影响，已签发报告须通过版本生命周期处理。
